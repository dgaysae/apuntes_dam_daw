Durante la fase de codificación se realiza la labor de **programar** o **escribir código fuente**. 

Consiste en elegir un determinado lenguaje de programación, codificar toda la información anterior y llevarlo a código fuente.

Esta tarea la realiza el programador y tiene que cumplir exhaustivamente con todos los datos impuestos en el análisis y en el diseño de la aplicación. 

Las **características** deseables de todo código son:

* **Modularidad**: que esté dividido en trozos más pequeños.

* **Corrección**: que haga lo que se le pide realmente.

* **Fácil de leer**: para facilitar su desarrollo y mantenimiento futuro.

* **Eficiencia**: que haga un buen uso de los recursos.

* **Portabilidad**: que se pueda implementar en cualquier equipo.

Durante esta fase, el código pasa por diferentes estados: 

* **Código fuente**: es el escrito por los programadores en algún editor de texto. Se escribe usando algún lenguaje de programación de alto nivel y contiene el conjunto de instrucciones necesarias.

* **Código objeto**: es el código binario resultado de **compilar el código fuente**. La compilación es la traducción de una sola vez del programa, y se realiza utilizando un compilador.

ℹ️ **Nota** ℹ️  
Los lenguajes interpretados no se compilan, se interpretan. La interpretación es la traducción y ejecución simultánea del programa línea a línea.

El código objeto no es directamente inteligible por el ser humano, pero tampoco por la computadora. Es un código intermedio entre el código fuente y el ejecutable y sólo existe si el programa se compila, ya que si se interpreta (traducción línea a línea del código) se traduce y se ejecuta en un solo paso sin generar código objeto.

* **Código ejecutable**: es el código binario resultante de **enlazar los archivos de código objeto con ciertas rutinas y bibliotecas** necesarias. El sistema operativo será el encargado de cargar el código ejecutable en memoria RAM y proceder a ejecutarlo.

  También es conocido como **código máquina** que la computadora entiende y, por tanto, puede ejecutar. 

## 4.1. Algoritmos

Para realizar un programa es necesario idear previamente un algoritmo. Esto es importante hasta el extremo de que, sin algoritmo, no existiría el programa. 

Un algoritmo es **una secuencia ordenada de pasos que conducen a la solución de un problema**. Los algoritmos tienen tres características fundamentales: 

* Son **precisos**, es decir, deben indicar el orden de realización de los pasos.

* Están **bien definidos**, es decir, si se sigue el algoritmo dos veces usando los mismos datos, debe proporcionar la misma solución.

* Son **finitos**, esto es, deben completarse en un número determinado de pasos. 

Por ejemplo, vamos a diseñar un algoritmo simple que determine si un número `N` es par o impar:
```
Inicio  
    Si N es divisible entre 2, entonces ES PAR  
    Si N no es divisible entre 2, entonces ES IMPAR  
Fin 
```


Si te fijas bien, este algoritmo cumple las tres condiciones enumeradas anteriormente (precisión, definición y finitud) y resuelve el problema planteado. Lógicamente, al ordenador no le podemos dar estas instrucciones tal y como las hemos escrito, sino que habrá que expresarlo en un lenguaje de programación. **El algoritmo es la fase previa a la codificación**.

Un ejemplo de ello son las recetas de cocina, manuales de instrucciones, etc.

Los algoritmos pueden representarse de muchas formas. Las más populares son:

* Lenguaje natural.

* Pseudocódigo.

* Diagramas de flujo.

* Diagramas de Nassi-Shneiderman.

El **primer paso** que se ha de dar antes de escribir una sola línea de código es la **elaboración previa de un algoritmo** que, como hemos visto, es un conjunto de pasos a seguir para obtener la solución del problema. El algoritmo lo diseñamos en **pseudocódigo** y con él, la codificación posterior a algún lenguaje de programación determinado será más rápida y directa. Mediante el pseudocódigo, se puede representar cualquier actividad diaria, desde la compra del pan hasta el cálculo de nóminas de una empresa.

Además del pseudocódigo, podemos representar gráficamente un algoritmo mediante diagramas de flujo.

## 4.2. Código fuente

El **código fuente** es el conjunto de **instrucciones** que la **computadora** deberá realizar, escritas por los programadores en algún **lenguaje de alto nivel**.

```java
public class HolaMundo {  
    public static void main(String args) {  
        System.out.println("¡Hola, Mundo!");  
    }  
}
```

Este conjunto de instrucciones **no es directamente ejecutable por la máquina**, sino que deberá ser traducido al lenguaje máquina, que la computadora será capaz de entender y ejecutar.

Para **obtener el código fuente** de una aplicación informática:

1. Se debe partir de las etapas anteriores de **análisis y diseño**.

2. Se diseñará un **algoritmo** que simbolice los pasos a seguir para la resolución del problema. 

3. Se elegirá una **lenguajes de programación** de alto nivel apropiado para las características del software que se quiere codificar. 

4. Se procederá a la **codificación** del algoritmo antes diseñado.

La culminación de la obtención de **código fuente** es un documento con la codificación de todos los módulos, funciones, bibliotecas y procedimientos necesarios para codificar la aplicación. 

Pero la máquina no entiende este código, así que hay que **traducirlo**, obteniendo así un código equivalente en binario llamado **código objeto**. 

Un aspecto importante a tener en cuenta es su licencia. Así, en base a ella, podemos distinguir **dos tipos de código fuente**: 

* **Código fuente abierto**: aquel que está disponible para que cualquier usuario pueda estudiarlo, modificarlo o reutilizarlo. Es *open source iniciative*.

* **Código fuente cerrado**: código que no se puede editar ya que no se da permiso para editarlo.

## 4.3. Código objeto

> [!note] Nota 
> En general se tendrá en mente Java para los ejemplos y conceptos como la compilación a *bytecode*, etc.

Es un **código intermedio**, resultado de traducir código fuente a un código equivalente formado por unos y ceros (binario) que aún no puede ser ejecutado directamente por la computadora. Es decir, es el código resultante de la compilación del código fuente.

Consiste en un bytecode (código binario) que está distribuido en varios archivos, cada uno de los cuales corresponde a cada programa fuente compilado. 

![ud01_ed_13_de_codigo_fuente_a_ejecutable.png](/img/user/adjuntos/1DAM_ED/Unidad_01/ud01_ed_13_de_codigo_fuente_a_ejecutable.png)

> [!note] Nota 
> Sólo se genera código objeto una vez que el código fuente está libre de errores sintácticos y semánticos.

El **proceso de traducción** de código fuente a código objeto puede realizarse de dos formas: 

* **Compilación**: el proceso de traducción se realiza sobre **todo el código fuente**, en un solo paso. Se crea un código objeto que habrá que enlazar. El software responsable se llama compilador.

* **Interpretación**: el proceso de traducción del código fuente se realiza **línea a línea** y cada línea se ejecuta justo cuando es traducida. No existe código objeto intermedio. El software responsable se llama **intérprete**. El proceso de traducción es más lento que en el caso de la compilación, pero es recomendable cuando el programador es inexperto, ya que la detección de errores es más detallada.

> [!note] Nota 
> El código objeto es código binario, pero no puede ser ejecutado por la computadora.
> En caso de Java, como hemos comentado antes, el código objeto es un *bytecode*.
> En cualquiera de los dos casos, es un código que puede ejecutarse bien por el procesador o, como en Java, se reconvierte de *bytecode* a **binario**, que **en última instancia es el código que entiende el procesador**.

## 4.4. Código ejecutable

El **código ejecutable** es el resultado de enlazar los archivos de código objeto y consta de un único archivo que puede ser directamente ejecutado por la computadora. No necesita ninguna aplicación externa. Este archivo es ejecutado y controlado por el sistema operativo. 

Para obtener un sólo archivo ejecutable habrá que **enlazar todos los archivos de código objeto**, a través de un software llamado ***linker*** (enlazador) y obtener así un único archivo que ya sí que es ejecutable directamente por la computadora. 

En el esquema de generación de código ejecutable vemos el proceso completo para la generación de ejecutables.

![Compilar a bytecode y ejecutar dicho bytecode en la JVM](https://docs.oracle.com/javase/tutorial/figures/getStarted/getStarted-compiler.gif)
> Compilar a bytecode y ejecutar dicho bytecode en la JVM

1. Usando un editor o un IDE, **escribimos el código fuente** con algún lenguaje de programación. En la figura sería `MyProgram.java`.

2. A continuación, el código fuente se compila obteniendo un **código objeto** o **bytecode** (`MyProgram.class`).

3. Ese **bytecode** se envía a la **máquina virtual** (la <abbr title="Java Virtual Machine">JVM</abbr>, que veremos en el siguiente punto) que lo convierte en **código máquina**, directamente ejecutable por la computadora.

## 4.5. Máquinas virtuales

Una máquina virtual es un tipo especial de software cuya misión es **separar el funcionamiento del ordenador de los componentes hardware instalados**. 

Esta capa de software desempeña un papel muy importante en el funcionamiento de los lenguajes de programación, tanto compilados como interpretados. 

Con el uso de máquinas virtuales podremos **desarrollar y ejecutar una aplicación sobre cualquier equipo**, independientemente de las características concretas de los componentes físicos instalados y del sistema operativo que tengan instalado. Esto garantiza la portabilidad de las aplicaciones. 

Las **funciones principales** de una máquina virtual son las siguientes: 

* Garantiza que las aplicaciones sean **portables**. 

* Reserva memoria para los objetos que se crean y libera la memoria no utilizada. 

* Se comunica con el sistema donde se instala la aplicación (huésped), para el control de los dispositivos hardware implicados en los procesos. 

* Cumple las normas de seguridad de las aplicaciones. 

Características de la máquina virtual:

* Cuando el código fuente se compila se obtiene **código objeto** (bytecode, código intermedio). 

* Para ejecutarlo en cualquier máquina se requiere tener **independencia respecto al hardware** concreto que se vaya a utilizar. 

* Para ello, la máquina virtual **aísla la aplicación** de los detalles físicos del equipo en cuestión. 

* Funciona como una **capa de software** de bajo nivel y actúa como puente entre el bytecode de la aplicación y los dispositivos físicos del sistema. 

* La Máquina Virtual **veriﬁca** todo el bytecode antes de ejecutarlo. 

* La Máquina Virtual **protege direcciones de memoria**. 

La máquina virtual actúa de **puente entre la aplicación y el hardware** concreto del equipo donde se instale. 

Por ello para cada sistema operativo se debe descargar la versión correspondiente de la JVM que será la encargada de convertir todo el código que escriben los programadores en código que pueda entender el equipo, descargándoles a éstos de todos los problemas que conlleva el cambio de plataforma. 

> [!example] Ejemplo 
> La [**Agencia Tributaria Española**](https://sede.agenciatributaria.gob.es/) desarrolla todo su software para los ciudadanos en esta plataforma.

## 4.6. Frameworks

Un **framework** es una **estructura** que proporciona al programador un conjunto de herramientas, bibliotecas, reglas y componentes reutilizables que permite desarrollar proyectos de software sin partir de cero.

Se trata de una plataforma software donde están definidos programas soporte, bibliotecas, lenguaje interpretado, etc. que ayuda a desarrollar y unir los diferentes módulos o partes de un proyecto. 

Con el uso de framework se puede invertir más tiempo en el análisis de requerimientos del sistema y las especificaciones técnicas de la aplicación, ya que **la tarea laboriosa de los detalles de programación se mitiga en gran medida**.

Entre las ventajas de utilizar un framework tenemos: 

* El **desarrollo** de software es **más rápido**. 

* Reutilización de partes de código para otras aplicaciones. 

* Diseño uniforme del software. 

* Portabilidad de aplicaciones de un computador a otro, ya que los bytecodes que se generan a partir del lenguaje fuente podrán ser ejecutados sobre la misma máquina virtual para distintos sistemas.

Pero también existen inconvenientes: 

* Existe una **gran dependencia** del código respecto al framework utilizado (si se cambia de framework en versiones futuras, habrá que reescribir gran parte del código). 

* La instalación e implementación del framework en el equipo de desarrollo **consume muchos recursos del sistema**.

Los frameworks más populares son: 

* [**.NET**](https://dotnet.microsoft.com/es-es/) inicialmente era un **framework** de Microsoft (.NET Framework) diseñado sólo para el sistema Windows. En la actualidad es, además, **una plataforma** de desarrollo de software de código abierto más robusta y eficiente que permite desarrollar aplicaciones multiplataforma (desde la versión 5).

  Ofrece un conjunto de herramientas y librerías para facilitar el desarrollo, como el "[Visual Studio .NET](https://visualstudio.microsoft.com/es/vs/features/net-development/)" que nos da facilidades para construir aplicaciones.

  Entre estas librerías también está el **Common Language Runtime** (CLR) que se encarga de la ejecución del código en distintas plataformas (Windows, Linux, Mac OS). Y lo hace porque convierte el código fuente a **Lenguaje Intermedio** (CIL) y luego lo compila a código de máquina específico de la plataforma en tiempo de ejecución.

  Permite crear aplicaciones tanto de escritorio como web y se pueden desarrollar usando una gran variedad de lenguajes: C#, Visual Basic, F#... ¡incluso Cobol .NET! 

* [**Spring de Java**](https://spring.io/projects/spring-framework). Son conjuntos de bibliotecas (API's) para el desarrollo y ejecución de aplicaciones. Es de código abierto y simplifica y agiliza enormemente el desarrollo de aplicaciones en Java ya que los desarrolladores pueden centrarse más en la lógica de negocio en lugar de en tareas repetitivas de configuración y estandarización.

  Ofrece un conjunto de herramientas y librerías para manejar diversos aspectos como la **gestión de dependencias**, la conectividad a bases de datos, la seguridad y la creación de aplicaciones web y microservicios

## 4.7. Entornos de ejecución

Un **entorno de ejecución** es un **servicio de máquina virtual** que sirve como base software para la ejecución de programas. En ocasiones, pertenece al propio sistema operativo, pero también se puede instalar como software independiente que funcionará por debajo de la aplicación. Es decir, es un **conjunto de utilidades que permiten la ejecución de programas**.

A la hora de hablar de ejecución de un programa es común ver el término **runtime**. Éste puede entenderse desde dos puntos de vista:

* Se refiere al **tiempo de ejecución** de un programa.

* Se trata de un **entorno de ejecución**, es decir, un software que proporciona los recursos y funcionalidades necesarias para que un programa pueda ejecutarse.

  Ejemplos: **<abbr title="Java Runtime Environment">JRE</abbr>** y el **.NET** de Microsoft.

Durante la ejecución, los entornos **se encargan de**: 

* **Configurar la memoria** principal disponible en el sistema. 

* **Enlazar los archivos del programa** con las bibliotecas existentes y con los subprogramas creados. Considerando que las bibliotecas son el conjunto de subprogramas que sirven para desarrollar o comunicar componentes software pero que ya existen previamente y los subprogramas serán aquellos que hemos creado a propósito para el programa. 

* **Depurar los programas**: comprobar la existencia (o no existencia) de errores semánticos del lenguaje (los sintácticos ya se detectaron en la compilación). 

### 4.7.1. Funcionamiento del entorno de ejecución

El entorno de ejecución está formado por la **máquina virtual** y las **API[^2]**. Estos dos componentes se suelen distribuir en un mismo paquete ya que deben ser compatibles entre sí.

El entorno funciona como intermediario entre el **código fuente** y el **sistema operativo** ya que permite ejecutar el uno en el otro. 

Sin embargo, no es suficiente para desarrollar nuevas aplicaciones.

#### <abbr title="Java Runtime Environment">JRE</abbr>

A continuación se explica el funcionamiento, instalación, configuración y primeros pasos del JRE de Java. Aunque con sus peculiaridades, puede hacerse extensible a otros lenguajes de programación.

**¿Qué es el JRE?** 

JRE es el *Java Runtime Environment* o entorno de Java en tiempo de ejecución. Proporciona el entorno necesario para que un programa Java pueda ejecutarse y funcione en cualquier sistema operativo.

**¿Qué elementos componen el JRE?** 

El JRE se compone, entre otros componentes, de:

* La **Máquina Virtual de Java** (JVM) es el software que permite a las aplicaciones escritas en Java ejecutarse en cualquier plataforma, ya que actúa como un intérprete que ejecuta el **bytecode** (código binario intermedio) de Java.

* Las **bibliotecas de clases** que implementan el API estándar de Java.

> [!note] Nota 
> La JMV y la API de Java son consistentes entre sí, por eso se distribuyen en un mismo paquete.

* El **ClassLoader** es una parte de la JVM que carga dinámicamente las clases Java en memoria cuando son necesarias para ejecutar un programa. Es decir, funciona bajo demanda.

Estos y otros componentes hacen posible la ejecución de programas Java en distintas plataformas.

**JRE y JDK** son dos componentes esenciales del desarrollo de aplicaciones Java. JRE es el entorno de ejecución de Java, que es necesario para ejecutar aplicaciones Java. JDK (*Java Development Kit*) es el kit de desarrollo de Java, que contiene todo lo que necesita para desarrollar aplicaciones Java, incluido el JRE.

De hecho, el JRE se distribuye junto al JDK. Es más, el JDK incluye todo el JRE, que a su vez contiene la JVM, las bibliotecas de clases y otros componentes necesarios para ejecutar aplicaciones Java, además de las herramientas de desarrollo como el compilador. 

![ud02_ed_14_classloader.png](/img/user/adjuntos/1DAM_ED/Unidad_02/ud02_ed_14_classloader.png)

**Principales diferencias entre JRE y JDK.**

|  | JRE | JDK |
| ----- | ----- | ----- |
| **Propósito** | Ejecutar aplicaciones Java | Desarrollar aplicaciones Java |
| **Componentes** | Máquina virtual Java (JVM), bibliotecas de clases Java, archivos de configuración | JRE, compilador[^3] Java, depurador[^4] Java, herramientas de documentación Java, etc. |
| **Destinado a...** | Usuarios finales | Desarrolladores |



[^2]:  Una API​ es una pieza de código que permite a dos aplicaciones comunicarse entre sí para compartir información y funcionalidades. ([Wikipedia](https://es.wikipedia.org/wiki/API), 2025)

[^3]:  El compilador convierte el código fuente escrito en Java en bytecode.

[^4]:  El depurador permite ejecutar un programa paso a paso, detectar y diagnosticar errores y entender su funcionamiento interno al examinar el valor de las variables.
