**JavaFX** es una plataforma de interfaz de usuario rica y moderna para aplicaciones de escritorio Java. A diferencia de Swing, JavaFX utiliza una arquitectura basada en **gráficos de escena** (*Scene Graph*).

Los componentes gráficos en JavaFX se llaman **nodos** (*Node*) y se organizan en una jerarquía de árbol.

JavaFX tiene múltiples ventajas sobre Swing, como, por ejemplo:

* Permite una manipulación más sencilla de la estructura de la interfaz gráfica y facilita la animación y los efectos visuales.

* Tiene un diseño más moderno y estilizado. En concreto, permite el uso de CSS para personalizar la apariencia de la interfaz de usuario.

* Organización del código más fácil de seguir y de leer.

* Simplificación de la gestión de eventos.

* API de multimedia integrada para reproducir audio o video de manera nativa.

* Soporte para arrastrar y soltar.

A pesar de estas ventajas indudables, hay que tener en cuenta que existen muchísimas aplicaciones Java que están funcionando con Swing, que es una tecnología mucho más estable y madura, por lo que deberías conocer ambas formas de crear interfaces gráficos si vas a dedicarte profesionalemente al desarrollo de aplicaciones con Java.

## 2.1. Arquitectura típica de una aplicación con JavaFX

Vamos a enumerar los elementos típicos de cualquier aplicación JavaFX. En la siguiente sección, veremos muchos de estos elementos en un ejemplo concreto, para que sean más fáciles de asimilar.

Todas las aplicaciones JavaFX suelen tener:

1. **Una clase principal (`Main`):** La aplicación JavaFX debe tener una clase principal que extiende `javafx.application.Application`. En esta clase se ubica el método **`main()`**. La clase principal es la responsable de iniciar la aplicación y cargar la escena (o ventana) de inicio.

2. **`Stage` y `Scene`:** Una `Stage` es una ventana de la aplicación. Las aplicaciones JavaFX deben tener al menos una `Stage`, pero pueden tener varias. La `Scene` contiene la jerarquía de nodos que se mostrarán en dentro de la `Stage`.

3. **Controlador:** La lógica de la interfaz de usuario y la manipulación de eventos se gestionan a menudo mediante un controlador. Un controlador no es más que una clase que se asocia con un archivo FXML y se encarga de manejar eventos y la lógica de la interfaz de usuario (Los archivos FXML son archivos XML que se utilizan para definir la interfaz de usuario de forma declarativa; enseguida hablamos de ellos).

4. **Modelo:** Aunque JavaFX no impone una estructura de modelo-vista-controlador (MVC) estricta, muchos desarrolladores eligen seguir un diseño similar. El modelo, en esta arquitectura, representa los datos y la lógica de la aplicación.

5. **Vistas:** Las vistas son los elementos visuales de la interfaz de usuario. Pueden definirse en código Java o en archivos FXML.

6. Los **controles y nodos** de JavaFX (botones, tablas, etc.) se utilizan para construir la interfaz de usuario.

7. **CSS (opcional):** Se pueden aplicar hojas de estilo CSS para personalizar la apariencia de los nodos y controles.

8. **Eventos y Listeners:** JavaFX, como Swing, utiliza un sistema de eventos para manejar la interacción del usuario. Se pueden asociar métodos en el controlador con eventos en la interfaz de usuario, como clics de botón o cambios en campos de texto.

9. **Propiedades:** JavaFX ofrece propiedades observables y *bindings*, lo que facilita la actualización automática de la interfaz de usuario en respuesta a cambios en los datos del modelo.

## 2.2. Comprendiendo cómo funciona JavaFX con un ejemplo

La mejor forma de que comprendas los conceptos anteriores es verlos en acción en un ejemplo sencillo. Eso te servirá para adaptarlos y aplicarlos a tus propias aplicaciones.

Vamos a ver el código de una aplicación gráfica que pide al usuario un número y muestra la **tabla de multiplicar** de ese número.

### 2.2.1. La clase principal (`Main`)

La clase principal (`MultiplicationTableApp.java`) carga el archivo FXML y configura la escena principal.

```java
import javafx.application.Application;
import javafx.fxml.FXMLLoader;
import javafx.scene.Parent;
import javafx.scene.Scene;
import javafx.stage.Stage;

public class MultiplicationTableApp extends Application {

    @Override
    public void start(Stage primaryStage) throws Exception {
        Parent root = FXMLLoader.load(
                        getClass().getResource("MultiplicationTable.fxml"));
        primaryStage.setTitle("Multiplication Table App");
        primaryStage.setScene(new Scene(root, 400, 300));
        primaryStage.show();
    }

    public static void main(String[] args) {
        launch(args);
    }
}
```

El método **`main()`** siempre llama a **`launch(args)`**, un método proporcionado por la clase `Application` que se encarga de iniciar el entorno de ejecución de JavaFX.

Este método, a su vez, se encarga de llamar al método **`start(Stage primaryStage)`** de nuestra clase `Application` cuando todo el entorno de JavaFX está listo para funcionar.

Este método, **`start(Stage primaryStage)`**, es el punto de entrada específico de JavaFX. Es decir, cualquier aplicación JavaFX empieza a ejecutarse *realmente* por aquí. Y el parámetro **`primaryStage`** es la ventana principal de la aplicación.

Fíjate en que lo primero que hace el método **`start()`** es cargar un archivo FXML, donde se definen todos los elementos del interfaz de usuario (veremos ese archivo enseguida), y a continuación establece algunos parámetros generales de la aplicación como el título (con **`setTitle()`**) o el tamaño de la ventana (400 x 300).

Por último, y esto es lo más importante, la ventana de la aplicación se muestra con el método **`show()`**.

### 2.2.2. El archivo FXML

En este archivo se definen todos los elementos del interfaz gráfico de nuestra aplicación. Un ejemplo de archivo FXML sencillo podría ser el siguiente. Échale un vistazo con calma y luego lo comentamos.

```xml
<?xml version="1.0" encoding="UTF-8"?>

<?import javafx.geometry.Insets?>
<?import javafx.scene.control.Button?>
<?import javafx.scene.control.Label?>
<?import javafx.scene.control.TextField?>
<?import javafx.scene.layout.VBox?>

<VBox alignment="CENTER" spacing="20.0" 
      xmlns="http://javafx.com/javafx/21" 
      xmlns:fx="http://javafx.com/fxml/1"
      fx:controller="MultiplicationTableController">
   <children>
      <Label text="Tabla de multiplicar" />
      <TextField fx:id="numberInput" promptText="Escribe un número" />
      <Button onAction="#showTable" text="Calcular tabla" />
      <Label fx:id="resultLabel" styleClass="result-label" />
   </children>
</VBox>
```

En primer lugar tenemos una línea con la versión de XML y la codificación de caracteres.

Después hay una serie de **`<?import...>`**. Se utilizan para que Java importe las clases necesarias para nuestro interfaz de usuario. Como aquí vamos a usar un botón, un campo de texto y unas etiquetas, es eso lo que vamos a importar. 

El **`VBox`** es un **`layout`**, y funciona como los layouts de Swing. Se trata de un layout de diseño vertical, que coloca los elementos del interfaz en una única columna. Fíjate como especificamos la alineación de elementos (al centro), el espaciado (20) y el archivo controlador (`MultiplicationTableController`, que veremos después). Los otros dos atributos (`xmlns` y `xmlns:fx`) establecen el espacio de nombres de JavaFX para evitar conflictos con nombres de otras clases. *Estos dos atributos puedes omitirlos en aplicaciones sencillas sin que suela pasar nada catastrófico.*

Más abajo se encuentran las definiciones de cada uno de los **elementos del interfaz**:

* **`Label`**: Etiquetas, es decir, texto plano.  
* **`TextField`**: Un campo de texto.  
* **`Button`**: Un botón.

Fíjate en que algunos de los elementos tiene un id único que los distingue de los demás (atributo **`fx:id`**), además de sus propios atributos. Por ejemplo, el Label tiene atributo **`text`**, el TextField tiene un atributo **`promptText`** y el Button tiene un atributo **`onAction`** (donde se especifica el método que se ejecutará al hacer clic).

Algunos elementos tienen, además, un atributo **`styleClass`**. Este atributo se utiliza para asignarle a ese campo un estilo CSS.

El interfaz de usuario definido en el archivo FXML anterior se vería más o menos así una vez ejecutado:

![ud06_javafx_fxml_01.png](/img/user/adjuntos/1DAM_Programacion/Unidad_06/ud06_javafx_fxml_01.png)

Ten en cuenta que también se puede crear ese interfaz **sin usar FXML**, solo que es más engorroso: hay que crear el contenedor y luego ir agregándole los nodos uno a uno. Por ejemplo:

```java
VBox vbox = new VBox();
Button button1 = new Button("Botón 1");
Button button2 = new Button("Botón 2");
vbox.getChildren().add(button1);
vbox.getChildren().add(button2);
```

Sin embargo, hay situaciones donde esto puede ser lo más conveniente. Por ejemplo, si necesitamos crear un nodo del interfaz en tiempo de ejecución (para que aparezca, digamos, un campo de texto nuevo donde antes no había nada). Otro caso habitual es que necesitemos crear muchos nodos semejantes como, por ejemplo, cien campos de texto. Es más fácil entonces crearlos desde Java mediante un bucle que definir los cien elementos en el archivo FXML.

### 2.2.2. El controlador

Un controlador es una clase que se utiliza para manejar la lógica de la aplicación y la interacción de la interfaz de usuario definida en un archivo FXML. 

La principal responsabilidad de un controlador es **responder a eventos de usuario y realizar acciones en respuesta a esos eventos**.

El controlador para nuestra tabla de multiplicar puede ser más o menos así:

```java
import javafx.fxml.FXML;
import javafx.scene.control.Label;
import javafx.scene.control.TextField;

public class MultiplicationTableController {

    @FXML
    Label resultLabel;
    
    @FXML
    TextField numberInput;

    public void initialize() {
       // Método optativo.
       // Se usa si hay que inicializar algún nodo del interfaz.
       // (Por ejemplo, poner algún valor por defecto en alguna parte
       //  o cargar alguna imagen)
    }

    @FXML
    private void showTable() throws IOException {
        String tabla = "";
        int n = Integer.parseInt(numberInput .getText());
        for (int i = 1; i <= 10; i++) {
            tabla += n + " x " + i + " = " + (n*i) + "\n";
        }
        resultLabel.setText(tabla);
    }
}
```

¿Recuerdas que en el archivo FXML habíamos creado un botón y, en el atributo **`onAction`**, habíamos escrito `#showTable`? Pues bien, ese método **`showTable()`** tiene que existir en el controlador: es lo que se ejecutará al hacer clic en el botón.

También puede haber, **optativamente**, un método **`initialize()`**. Este método se ejecutará automáticamente después de cargar todos los componentes del archivo FXML. Suele usarse para inicializar elementos del interfaz (por ejemplo, para insertar una imagen en un nodo de tipo `ImageView`)

Además, aparecen dos atributos, **`resultLabel`** y **`numberInput`**, que coinciden exactamente en nombre y tipo con los campos definidos en el archivo FXML. De ese modo, nuestro controlador puede acceder a esa etiqueta y ese campo de texto y consultar sus propiedades o manipularlas.

Cada elemento del interfaz tiene un conjunto de métodos diferente para manipularlos. Por ejemplo, los nodos de tipo **`Label`** tienen un método **`setText()`** que permite modificar el texto que contienen, y los nodos de tipo **`TextField`** tienen un método **`getText()`** para consultar el texto que hay escrito en ellos. Esos son los dos métodos de los que se hace uso en este ejemplo.

Observa que, antes de declarar cada elemento de los que aparecen en el archivo FXML, en el controlador aparece la directiva **`@FXML`**. Esto es necesario para que el compilador de Java enlace correctamente los elementos definidos en el archivo FXML con los objetos del controlador.

No olvides que, para que todo funcione, hay que realizar los **`import`** correspondientes.

### 2.2.4. Modelo y vistas

Aunque JavaFX no impone una estructura de modelo-vista-controlador (MVC) estricta, muchos desarrolladores eligen seguir un diseño MVC.

En este diseño, el **modelo** es la clase donde se integra la lógica de la aplicación. Cosas como el acceso a ficheros, el acceso a bases de datos o las soluciones algorítmicas que tu aplicación requiera, suelen encontrar un buen acomodo en el modelo.

El ejemplo de la tabla de multiplicar es demasiado simple como para necesitar un modelo. Sin embargo, podíamos haber forzado las cosas para que la generación de la tabla de multiplicar, por ejemplo, se hicieran en una clase diferente del controlador. El controlador invocaría a esa clase para realizar los cálculos, recibiría los resultados y los enviaría al interfaz gráfico para mostrarlos.

Las **vistas** son los elementos visuales de la interfaz de usuario. Cualquier aplicación gráfica debe tener, al menos, una vista. Aunque pueden definirse con código Java, lo más cómodo con JavaFX es hacerlo en archivos FXML como el que hemos visto antes. Necesitarás un archivo FXML para cada vista de tu aplicación.

### 2.2.5. CSS (opcional)

El CSS, como en las páginas web, permite modificar fácilmente la apariencia de los componentes del interfaz. La ventaja de usar CSS es que es un lenguaje de estilo muy extendido y que casi todos los programadores conocen. Aunque el CSS de JavaFX no es exactamente CSS2.1 ni CSS3, se parece bastante.

El archivo o archivos con los estilos se ubica en `./src/main/resources`. Por ejemplo, `./src/main/resources/styles.css`

Dentro de ese archivo podríamos, por ejemplo, definir una reglas de estilo para los componentes del archivo FXML que pertenezcan a la clase `result-label`:

```css
.result-label {
    -fx-font-size: 14pt;
    -fx-text-fill: green;
}
```

Observa que hemos utilizado *selectores de clase*, como **.result-label**, para aplicar nuestro estilo, igual que en CSS convencional. También pueden usarse *selectores de id* (con \#) y *pseudoclases* (con :).

Si revisas el archivo FXML que aparece más arriba, verás que hay un elemento del interfaz con un atributo **styleClass="result-label"**. En concreto, el Label donde se muestra la tabla de multiplicar:

 `<Label fx:id="resultLabel" styleClass="result-label"/>`

Para que el archivo CSS se cargue correctamente, hay que indicarlo en el contenedor primario del archivo FXML. En el ejemplo anterior, lo haríamos así:

`<VBox stylesheets="styles.css" resto-de-atributos-del-vbox>`

Las reglas de estilo del CSS de JavaFX son semejantes a las del CSS convencional, pero no iguales. Aquí te dejo algunas de las más habituales:

- **`-fx-background-color`**: Define el color de fondo del elemento.
- **`-fx-control-inner-background`**: Lo mismo que el anterior (si el otro no funciona).
- **`-fx-text-fill`**: Define el color del texto.
- **`-fx-font-size`**: Define el tamaño de la fuente.
- **`-fx-font-family`**: Define la familia de la fuente.
- **`-fx-padding`**: Define el espacio entre el contenido del elemento y sus bordes.
- **`-fx-border-color`**: Define el color del borde.
- **`-fx-border-width`**: Define el ancho del borde.
- **`-fx-font-weight: bold;`**  Pone el texto en negrita.
- **`-fx-font-style: italic;`**  Pone el texto en cursiva.
- **`-fx-alignment: CENTER;`**  Alinea el texto al centro (también admite los valores `LEFT`, `RIGHT`, `TOP`, `BOTTOM`, y combinaciones de ellos, como `TOP_CENTER`)

### 2.2.6. Eventos y Listeners

JavaFX, como Swing, utiliza un sistema de eventos para manejar la interacción del usuario. Se pueden asociar métodos en el controlador con eventos en la interfaz de usuario, como clics de botón o cambios en campos de texto.

En el ejemplo de la tabla de multiplicar hay un **evento** (**clic**) y su correspondiente **`listener`** (método **`showTable()`** de la clase controladora)

Este método se ejecutará cuando se produzca el evento clic sobre el objeto adecuado. En este caso, el método obtiene el número introducido por el usuario, genera la tabla de multiplicar correspondiente y actualiza la interfaz de usuario con el resultado (ver código más arriba).

## 2.3. Nodos de JavaFX

Los nodos, como hemos visto en el ejemplo, son los objetos gráficos que se pueden insertar en el interfaz de usuario. A continuación mostraremos una lista de los más habituales, aunque por supuesto hay muchos más:

### 2.3.1. Contenedores

* **`Pane`**: es una clase base para todos los contenedores en JavaFX. Proporciona un área rectangular en la que se pueden colocar otros nodos.

* **`VBox`** y **`HBox`**: `VBox` (Vertical Box) y `HBox` (Horizontal Box) son contenedores que organizan sus nodos secuencialmente, ya sea en una columna vertical o en una fila horizontal.

* **`BorderPane`**: contenedor que divide su área en cinco regiones: arriba, abajo, izquierda, derecha y centro, permitiendo colocar nodos en cada una de estas regiones.

(Ver la sección *layouts* más abajo para una lista más completa de contenedores)

### 2.3.2. Nodos de control: botones, campos de texto y más

* **`Button`**: representa un botón que puede disparar eventos cuando se hace clic.

* **`Label`**: representa una etiqueta de texto no editable.

* **`TextField`**: es un campo de texto que permite al usuario introducir un texto.

* **`TextArea`**: es un área de texto multilínea que permite al usuario introducir un texto.

* **`CheckBox`** y **`RadioButton`**: son controles de selección que permiten al usuario elegir opciones. Como en HTML, vamos.

* **`ComboBox`**: control desplegable que permite al usuario seleccionar un elemento de una lista.

* **`ListView`** y **`TreeView`**: controles de lista que permiten al usuario ver y seleccionar elementos de una lista o una estructura de árbol, respectivamente.

Aquí tienes un ejemplo sencillo donde se usan casi todos estos nodos.

En primer lugar, tendríamos el interfaz definido en un **archivo FXML**. Observa cómo se declaran cada uno de los nodos del interfaz.

```xml
<?xml version="1.0" encoding="UTF-8"?>

<?import javafx.scene.control.*?>
<?import javafx.scene.layout.VBox?>

<VBox spacing="10" xmlns="http://javafx.com/javafx"
      xmlns:fx="http://javafx.com/fxml"
      fx:controller="nombre-del-controlador">

    <Label text="Nombre:"/>
    <TextField fx:id="nameTextField"/>

    <Label text="Mensaje:"/>
    <TextArea fx:id="messageTextArea"/>

    <CheckBox text="Acepto los términos y condiciones" fx:id="checkBox"/>

    <RadioButton text="Opción 1" fx:id="radioOption1"/>
    <RadioButton text="Opción 2" fx:id="radioOption2"/>

    <ComboBox fx:id="comboBox" promptText="Selecciona una opción">
        <items>
            <FXCollections fx:factory="observableArrayList">
                <String fx:value="Opción A"/>
                <String fx:value="Opción B"/>
                <String fx:value="Opción C"/>
            </FXCollections>
        </items>
    </ComboBox>

    <Button text="Enviar" onAction="#handleSubmit"/>
</VBox>
```

Este sería el **controlador** para ese interfaz gráfico. Hemos añadido un manejador de eventos para capturar el clic de ratón.

```java
import javafx.collections.FXCollections;
import javafx.fxml.FXML;
import javafx.scene.control.*;

public class NombreDelControlador {
    @FXML
    private TextField nameTextField;

    @FXML
    private TextArea messageTextArea;

    @FXML
    private CheckBox checkBox;

    @FXML
    private RadioButton radioOption1;

    @FXML
    private RadioButton radioOption2;

    @FXML
    private ComboBox<String> comboBox;

    @FXML
    private void handleSubmit() {
        // Obtenemos los valores de los diferentes nodos
        String name = nameTextField.getText();
        String message = messageTextArea.getText();
        boolean accepted = checkBox.isSelected();
        // Obtener el valor de RadioButton seleccionado directamente
        ToggleGroup toggleGroup = radioOption1.getToggleGroup();
        RadioButton selectedRadio = 
                       (RadioButton) toggleGroup.getSelectedToggle();
        String radioOption = 
                       selectedRadio == null ? "" : selectedRadio.getText();
        String comboBoxOption = comboBox.getValue();

        // Mostramos esos valores por la consola
        System.out.println("Nombre: " + name);
        System.out.println("Mensaje: " + message);
        System.out.println("Aceptar términos: " + accepted);
        System.out.println("Opción de radio: " + radioOption);
        System.out.println("Opción de ComboBox: " + comboBoxOption);
    }
}
```

Y, por último, esta sería la clase principal:


### 2.3.3. Nodos gráficos

* **ImageView**: se utiliza para mostrar imágenes.

* **Canvas**: proporciona un área en la que se pueden realizar operaciones de dibujo.

* **WebView**: permite mostrar contenido web embebido en una aplicación JavaFX.

Probablemente el más habitual es **ImageView**, que nos permite insertar imágenes en nuestra ventana. Para crear un ImageView desde FXML, el código mínimo necesario es este:

```xml
<ImageView>
    <image>
        <Image url="@mi-imagen.jpg"/>
    </image>
</ImageView>
```

Al ImageView se le pueden añadir atributos como `fitHeight` y `fitWidth` para controlar su tamaño. También es útil el atributo `preserveRatio="true"` para asegurarte de que la imagen no se deforma.

### 2.3.4. Menús

Para crear menús, en JavaFX se utilizan varios nodos específicos destinados a gestionar la estructura de menús y sus elementos. Aquí algunos de los nodos principales que puedes utilizar:

* **`MenuBar`**: es un contenedor que contiene objetos de tipo Menu, que a su vez contienen objetos MenuItem. Puedes agregar varios menús horizontales a una barra de menús.

* **`Menu`**: representa un menú desplegable. Puedes agregar múltiples elementos de menú (MenuItem y otros submenús) dentro de un Menu.

* **`MenuItem`**: representa un elemento de menú individual. Puede contener texto, gráficos o incluso submenús.

* **`CheckMenuItem`**: es una extensión de MenuItem que puede tener un estado de selección (marcado o desmarcado). Es útil para opciones de menú que pueden estar activadas o desactivadas.

* **`RadioMenuItem`**: es otra extensión de `MenuItem` que se utiliza en grupos de elementos de menú. Solo un RadioMenuItem de un grupo puede estar seleccionado a la vez.

* **`ContextMenu`**: es un menú contextual que se muestra en respuesta a una acción del usuario, generalmente un clic derecho.

A continuación puedes ver un ejemplo simple de uso de algunas de estas clases. En este ejemplo, vamos a crear todos los nodos desde Java, pero recuerda que también se puede hacer con un archivo FXML.

```java
import javafx.application.Application;
import javafx.scene.Scene;
import javafx.scene.control.*;
import javafx.scene.layout.VBox;
import javafx.stage.Stage;

public class MenuExample extends Application {

    @Override
    public void start(Stage primaryStage) {
        primaryStage.setTitle("Ejemplo de Menú");

        // Barra de menús
        MenuBar menuBar = new MenuBar();

        // Menú "Archivo"
        Menu fileMenu = new Menu("Archivo");

        MenuItem newItem = new MenuItem("Nuevo");
        MenuItem openItem = new MenuItem("Abrir");
        MenuItem saveItem = new MenuItem("Guardar");
        MenuItem exitItem = new MenuItem("Salir");

        fileMenu.getItems().addAll(newItem, openItem, saveItem, 
                                   new SeparatorMenuItem(), exitItem);

        // Menú "Editar"
        Menu editMenu = new Menu("Editar");

        MenuItem cutItem = new MenuItem("Cortar");
        MenuItem copyItem = new MenuItem("Copiar");
        MenuItem pasteItem = new MenuItem("Pegar");

        editMenu.getItems().addAll(cutItem, copyItem, pasteItem);

        // Menú contextual
        ContextMenu contextMenu = new ContextMenu();
        MenuItem contextItem = new MenuItem("Opción de Menú Contextual");
        contextMenu.getItems().add(contextItem);

        // Área de contenido
        TextArea textArea = new TextArea();

        // Asociación del menú contextual a la área de texto
        textArea.setContextMenu(contextMenu);

        // Asociación de menús a la barra de menús
        menuBar.getMenus().addAll(fileMenu, editMenu);

        // Diseño de la interfaz
        VBox vbox = new VBox(menuBar, textArea);
        Scene scene = new Scene(vbox, 400, 300);
        primaryStage.setScene(scene);

        primaryStage.show();
    }

    public static void main(String[] args) {
        launch(args);
    }
}
```

#### Reutilizar menús

A menudo, las aplicaciones tienen varias vistas (o ventanas diferentes) que comparten el mismo menú. Si este es tu caso, no es necesario que programes el mismo menú varias veces. Para reutilizar tu menú, basta con hacer lo siguiente:

1. Diseña tu menú como una vista FXML. Puedes utilizar SceneBuilder (ver más adelante) o hacerlo a mano.

2. Guarda tu menú en un archivo llamado menu.fxml o algo parecido.

3. Inserta ese menú en cualquier otro archivo FXML escribiendo esto en el punto de tu vista donde quieras que el menú aparezca:  
  `<fx:include source="menu.fxml"/>`  

### 2.3.5. Controles especiales

* **`DatePicker`** y **`TimePicker`**: proporcionan controles para la selección de fechas y horas, respectivamente.

* **`ProgressBar`**: muestra una barra gráfica de progreso.

* **`Slider`**: permite al usuario seleccionar un valor de un rango continuo. 

* **`ScrollBar`**: ScrollBar proporciona una barra que se puede desplazar horizontal o verticalmente.

```java
import javafx.application.Application;

        Scene scene = new Scene(root, 300, 200);

        primaryStage.setScene(scene);

    }
```

## 2.4. Eventos

Los principales eventos con los que puedes manejar las aplicaciones JavaFX son los siguientes:

* **`ActionEvent`**: Ocurre cuando se realiza una acción en un nodo interactivo, como hacer clic en un botón. El evento concreto depende del nodo. Si es un botón, `ActionEvent` es "hacer clic en el botón", por ejemplo.

* **`MouseEvent`**: Engloba eventos relacionados con el movimiento y clics del mouse, incluyendo clics simples y dobles, arrastre, entre otros.

* **`KeyEvent`**: Se activa cuando ocurre un evento de teclado, como presionar, soltar o mantener presionada una tecla.

* **`DragEvent`**: Relacionado con eventos de arrastre y suelta, se dispara durante la interacción de arrastre de un nodo.

* **`WindowEvent`**: Ocurre cuando hay cambios en el estado de la ventana, como apertura, cierre, activación, etc.

* **`ScrollEvent`**: Relacionado con eventos de desplazamiento del mouse, se activa cuando se realiza un desplazamiento con la rueda del mouse.

* **`ZoomEvent`**: Se activa durante eventos de zoom, como acercar o alejar, a menudo asociado con gestos táctiles.

* **`SwipeEvent`**: Relacionado con eventos de deslizamiento, típicamente asociados con gestos táctiles.

* **`InputMethodEvent`**: Ocurre durante eventos de entrada de método, como la composición de texto en idiomas no latinos.

* **`MediaEvent`**: Relacionado con eventos de reproducción multimedia, como inicio, pausa o finalización de la reproducción.

* **`ContextMenuEvent`**: Relacionado con la aparición y desaparición de menús contextuales.

Un evento como, por ejemplo, `MouseEvent`, puede producirse por diferentes eventos de ratón, como hacer clic, hacer doble clic o arrastrar y soltar. Para saber exactamente qué es lo que el usuario ha hecho, el manejador del evento tiene que acceder a las propiedades y métodos del evento que, como es lógico, son diferentes para cada tipo de evento. Por lo tanto, tendrás que bucear en la documentación para usar cada tipo de evento según su propio estilo.

Observa este ejemplo de manejador de evento `MouseEvent` y observa cómo nos las podemos apañar para averiguar los detalles concretos del evento:

```java
    private void handleMouseEvent(MouseEvent event) {
        if (event.getEventType() == MouseEvent.MOUSE_CLICKED) {
            System.out.println("Clic simple");
        } else if (event.getEventType()==MouseEvent.MOUSE_DOUBLE_CLICKED) {
            System.out.println("Doble clic");
        }

        int clickCount = event.getClickCount();
        if (clickCount == 1) {
            System.out.println("Clic simple");
        } else if (clickCount == 2) {
            System.out.println("Doble clic");
        }

        if (event.isPrimaryButtonDown()) {
            System.out.println("Botón izquierdo presionado");
        }

        if (event.isSecondaryButtonDown()) {
            System.out.println("Botón derecho presionado");
        }
    }
```

## 2.5. Manejadores de eventos (listeners)

Los listeners o manejadores de eventos (EventHandlers, en terminología de JavaFX) se construyen de forma diferente si usas FXML o si montas tu interfaz directamente desde Java. Yo te recomiendo usar FXML.

1. **Creando listeners con FXML**  
  Cuando defines EventHandlers en FXML, estás incorporando la lógica directamente en la descripción de la interfaz de usuario. Esto es mejor para mantener una separación visual entre la estructura de la interfaz y la lógica de la aplicación. Además, es mucho más fácil escribir el código así.

  Crear un EventHandler desde el **archivo FXML** es tan fácil como:

  ```xml
  <Button fx:id="myButton" text="Haz clic" onAction="#handleButtonClick"/>
  ```

En el **controlador** correspondiente bastará con que crear el método **`handleButtonClick()`**:

```java
public class Controller {
    @FXML
    private Button myButton;

    @FXML
    private void handleButtonClick() {
        System.out.println("Botón clicado!");
    }
}
```

2. **Creado listeners con código Java**  
  Cuando defines `EventHandler` directamente en el código Java, estás centralizando la lógica de la aplicación en el código. Esto puede ser beneficioso cuando prefieres tener más control sobre la lógica y no quieres que la interfaz de usuario contenga demasiada información sobre el comportamiento de la aplicación, pero, en general, es más engorroso escribir el código de este modo.

   El mismo ejemplo anterior se escribiría así sin usar FXML. Observa cómo se añade el `EventHandle` con el método **`setOnAction()`**:

  ```java
  import javafx.application.Application;
  import javafx.scene.Scene;
  import javafx.scene.control.Button;
  import javafx.stage.Stage;
  
  public class Main extends Application {
  
      @Override
      public void start(Stage primaryStage) {
          Button myButton = new Button("Haz clic");
  
          myButton.setOnAction(event -> {
              System.out.println("Botón clicado!");
          });
  
          primaryStage.setScene(new Scene(myButton, 300, 200));
          primaryStage.setTitle("Ejemplo sin FXML");
          primaryStage.show();
      }
  
      public static void main(String[] args) {
          launch(args);
      }
  }
  ```

## 2.6. Contenedores (layouts)

En JavaFX, los layouts son **contenedores** que se utilizan para organizar y controlar la disposición de los nodos (los componentes gráficos) en la interfaz de usuario.

Los layouts ayudan a gestionar el espacio, el tamaño y la alineación de los nodos, facilitando así la creación de interfaces de usuario flexibles y dinámicas, que se puedan adaptar por sí solas a cualquier entorno de ejecución. 

La elección del layout dependerá de la estructura específica que desees lograr en tu interfaz de usuario. Además, se pueden combinar y anidar diferentes layouts para obtener diseños más complejos y personalizados.

Estos son los layouts más comunes en JavaFX:

* **`Pane`**: es una clase base para todos los contenedores en JavaFX. Es un contenedor sin diseño específico, y simplemente coloca los nodos hijos uno encima del otro. No suele utilizarse en aplicaciones reales.

* **`HBox`** y **`VBox`**: `HBox` (Horizontal Box) y `VBox` (Vertical Box) son contenedores que organizan sus nodos secuencialmente en una fila horizontal o columna vertical, respectivamente. Sirven para diseñar ventanas sencillas y con pocos elementos.

* **`BorderPane`**: este contenedor divide su área en cinco regiones: arriba, abajo, izquierda, derecha y centro. Esto facilita la colocación de nodos en áreas específicas de la pantalla.

* **`StackPane`**: apila sus nodos uno encima del otro. El nodo más reciente agregado se coloca en la parte superior de la pila.

* **`GridPane`**: organiza sus nodos en una cuadrícula de filas y columnas. Es especialmente útil cuando se necesita un diseño más complejo y preciso.

* **`FlowPane`**: organiza los nodos en una fila o columna y los "envuelve" automáticamente si no hay suficiente espacio en la pantalla.

* **`TilePane`**: es similar a `FlowPane`, pero trata de organizar sus nodos en celdas de tamaño uniforme de manera automática.

* **`AnchorPane`**: permite anclar los nodos a los bordes del contenedor o a puntos específicos dentro del mismo.

El siguiente esquema muestra cómo se distribuyen los elementos en cada uno de estos layouts:

![ud06_javafx_layouts_01.png](/img/user/adjuntos/1DAM_Programacion/Unidad_06/ud06_javafx_layouts_01.png)

Para utilizar estos contenedores, basta con crear una instancia del layout deseado, agregar nodos a él y luego colocar ese layout en la escena de la aplicación. Por ejemplo:

```java
HBox hbox = new HBox();
Button button1 = new Button("Botón 1");
Button button2 = new Button("Botón 2");
hbox.getChildren().addAll(button1, button2);

Scene scene = new Scene(hbox, 400, 200);
```

Por supuesto, también se pueden usar en los archivos FXML, como vimos en el ejemplo de la Tabla de Multiplicar, donde utilizábamos un VBox. En ese caso, el contenedor se indica en el archivo FXML:

```xml
<HBox alignment="CENTER" spacing="20.0" 
      xmlns="http://javafx.com/javafx/21" 
      xmlns:fx="http://javafx.com/fxml/1"
      fx:controller="NombreDelControlador">
   <children>
      <Button fx:id="button1" text="Botón 1">
      <Button fx:id="button2" text="Botón 2">
   </children>
</Hbox>
```

## 2.7. Scene Builder

Un archivo FXML donde se define la interfaz de usuario puede llegar a ser bastante complejo y tedioso de escribir. Para superar esta dificultad existen los **Scene Builders**, que son programas de diseño en los que se puede dibujar gráficamente el interfaz que deseamos y, a partir de él, **nos genera el archivo XML** correspondiente.

Existen varios Scene Builders en el mercado. Uno bastante extendido es el GluonHQ, que tiene licencia de software libre y es multisistema.

Usar un Scene Builder como el de Gluon es tan sencillo como:

1. Descargar e instalar la última versión de Scene Builder de la web [gluonhq.com](http://gluonhq.com)

2. Arrancar el programa

3. Dibujar el interfaz de usuario arrastrando y soltando.

4. Configurar los nodos del interfaz asignándoles nombres significativos y valores adecuados a las propiedades. Si se desea, añadir CSS para retocar el aspecto que tienen por defecto.

5. Guardar el trabajo en un archivo FXML que podremos usar directamente en nuestro proyecto.

## 1.8. Compilar aplicaciones con JavaFX

### 1.8.1. Compilar desde la línea de comandos

Tengo una mala noticia: las librerías de JavaFX no se distribuyen por defecto con el JDK de Java.

Esto quiere decir que no podrás compilar tu aplicación JavaFX a menos que te bajes el JDK de JavaFX. Esto, como es lógico, se hace de forma diferente según tu sistema operativo.

Además, el compilador de java no encontrará esas librerías porque se ubican en un directorio distinto. Para compilar correctamente la aplicación tendrás que indicar la ruta a JavaFX a tu compilador, así:

```bash
$ javac --module-path <ruta-a-tus-librerías-javafx>
        --add-modules <lista-de-módulos-que-necesitas> TuApp.java
```

Y luego tendrás que ejecutarlo así:

```bash
$ java --module-path <ruta-a-tus-librerías-javafx>
       --add-modules <lista-de-módulos-que-necesitas> TuApp
```

Por ejemplo, si nuestra aplicación necesita importar todos los controles de JavaFX, lo haríamos así:

```bash
$ javac --module-path lib/javafx-sdk-16/lib
        --add-modules javafx.controls -d out src/com/ejemplo/TuApp.java
$ java  --module-path lib/javafx-sdk-16/lib
        --add-modules javafx.controls -cp out com.ejemplo.TuApp
```

Lógicamente, debes sustituir las rutas de este ejemplo por la ruta adecuada en tu sistema operativo.

Para evitar este engorro cada vez que compilas, puedes modificar la variable de entorno CLASSPATH de tu sistema operativo, de manera que tenga en cuenta la ubicación de las librerías de JavaFX.

> [!info] En Linux 
> Abre un terminal y teclea esto (o bien añádelo a un script de inicio de sesión para que se ejecute automáticamente al iniciar sesión):
> ```bash
> $ export CLASSPATH=$CLASSPATH:/ruta/a/javafx-sdk-16/lib
> ```

> [!info] En Windows 
> 1. Abre el menú de inicio y busca "Variables de entorno".
> 2. En la ventana de Propiedades del sistema, haz clic en el botón "Variables de entorno".
> 3. En la sección "Variables del sistema", busca la variable CLASSPATH y haz clic en "Editar".
> 4. Agrega al final de la línea existente el path al directorio lib del JavaFX SDK. Por ejemplo, `C:\\ruta\\a\\javafx-sdk-16\\lib`

### 1.8.2. Compilar con NetBeans o IntelliJ IDEA

Compilar una aplicación JavaFX con **NetBeans** o cualquier otro IDE que trabaje bien con Java, como **IntelliJ IDEA**, es muchísimo más sencillo, por lo que es el método que te recomiendo.

> [!note] Nota 
> Los siguientes pasos se refieren a NetBeans, pero otros IDEs como Eclipse lo harán de forma semejante. Si prefieres trabajar con otros IDE o editores de código no específicos de Java, como [Visual Studio](https://visualstudio.microsoft.com/es/), tendrás que consultar en la documentación oficial la manera de compilar JavaFX desde tu editor.

1. Crea un proyecto nuevo y elige la categoría "**Java with Maven**" - "**FXML Java Maven Archetype**"

2. Si NetBeans detecta que JavaFX no está instalado en tu sistema, te ofrecerá la posibilidad de instalarlo en ese mismo instante. Pídele que lo haga por ti ("**Download and activate**") y se encargará de todo. Tendrás que aceptar el acuerdo de licencia.

3. Asigna un nombre a tu proyecto, como siempre.

Y listo: ya tienes una aplicación JavaFX funcionando y compilando en solo unos pasos. Además, esta aplicación viene con un par de controladores y un par de vistas sencillas que puedes reutilizar para tu propia aplicación, de manera que no tienes que empezar de cero.
