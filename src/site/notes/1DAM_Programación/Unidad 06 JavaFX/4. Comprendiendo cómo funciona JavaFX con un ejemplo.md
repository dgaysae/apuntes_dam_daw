La mejor forma de que comprendas los conceptos anteriores es verlos en acción en un ejemplo sencillo. Eso te servirá para adaptarlos y aplicarlos a tus propias aplicaciones.

Vamos a ver el código de una aplicación gráfica que pide al usuario un número y muestra la **tabla de multiplicar** de ese número.

## 4.1. La clase principal (`Main`)

La clase principal (`MultiplicationTableApp.java`) carga el archivo FXML y configura la escena principal.

```java
import javafx.application.Application;
import javafx.fxml.FXMLLoader;
import javafx.scene.Parent;
import javafx.scene.Scene;
import javafx.stage.Stage;

public class MultiplicationTableApp extends Application {

    @Override
    public void start(Stage primaryStage) throws Exception {
        Parent root = FXMLLoader.load(
                        getClass().getResource("MultiplicationTable.fxml"));
        primaryStage.setTitle("Multiplication Table App");
        primaryStage.setScene(new Scene(root, 400, 300));
        primaryStage.show();
    }

    public static void main(String[] args) {
        launch(args);
    }
}
```

El método **`main()`** siempre llama a **`launch(args)`**, un método proporcionado por la clase `Application` que se encarga de iniciar el entorno de ejecución de JavaFX.

Este método, a su vez, se encarga de llamar al método **`start(Stage primaryStage)`** de nuestra clase `Application` cuando todo el entorno de JavaFX está listo para funcionar.

Este método, **`start(Stage primaryStage)`**, es el punto de entrada específico de JavaFX. Es decir, cualquier aplicación JavaFX empieza a ejecutarse *realmente* por aquí. Y el parámetro **`primaryStage`** es la ventana principal de la aplicación.

Fíjate en que lo primero que hace el método **`start()`** es cargar un archivo FXML, donde se definen todos los elementos del interfaz de usuario (veremos ese archivo enseguida), y a continuación establece algunos parámetros generales de la aplicación como el título (con **`setTitle()`**) o el tamaño de la ventana (400 x 300).

Por último, y esto es lo más importante, la ventana de la aplicación se muestra con el método **`show()`**.

## 4.2. El archivo FXML

En este archivo se definen todos los elementos del interfaz gráfico de nuestra aplicación. Un ejemplo de archivo FXML sencillo podría ser el siguiente. Échale un vistazo con calma y luego lo comentamos.

```xml
<?xml version="1.0" encoding="UTF-8"?>

<?import javafx.geometry.Insets?>
<?import javafx.scene.control.Button?>
<?import javafx.scene.control.Label?>
<?import javafx.scene.control.TextField?>
<?import javafx.scene.layout.VBox?>

<VBox alignment="CENTER" spacing="20.0" 
      xmlns="http://javafx.com/javafx/21" 
      xmlns:fx="http://javafx.com/fxml/1"
      fx:controller="MultiplicationTableController">
   <children>
      <Label text="Tabla de multiplicar" />
      <TextField fx:id="numberInput" promptText="Escribe un número" />
      <Button onAction="#showTable" text="Calcular tabla" />
      <Label fx:id="resultLabel" styleClass="result-label" />
   </children>
</VBox>
```

En primer lugar tenemos una línea con la versión de XML y la codificación de caracteres.

Después hay una serie de **`<?import...>`**. Se utilizan para que Java importe las clases necesarias para nuestro interfaz de usuario. Como aquí vamos a usar un botón, un campo de texto y unas etiquetas, es eso lo que vamos a importar. 

El **`VBox`** es un **`layout`**, y funciona como los layouts de Swing. Se trata de un layout de diseño vertical, que coloca los elementos del interfaz en una única columna. Fíjate como especificamos la alineación de elementos (al centro), el espaciado (20) y el archivo controlador (`MultiplicationTableController`, que veremos después). Los otros dos atributos (`xmlns` y `xmlns:fx`) establecen el espacio de nombres de JavaFX para evitar conflictos con nombres de otras clases. *Estos dos atributos puedes omitirlos en aplicaciones sencillas sin que suela pasar nada catastrófico.*

Más abajo se encuentran las definiciones de cada uno de los **elementos del interfaz**:

* **`Label`**: Etiquetas, es decir, texto plano.  
* **`TextField`**: Un campo de texto.  
* **`Button`**: Un botón.

Fíjate en que algunos de los elementos tiene un id único que los distingue de los demás (atributo **`fx:id`**), además de sus propios atributos. Por ejemplo, el Label tiene atributo **`text`**, el TextField tiene un atributo **`promptText`** y el Button tiene un atributo **`onAction`** (donde se especifica el método que se ejecutará al hacer clic).

Algunos elementos tienen, además, un atributo **`styleClass`**. Este atributo se utiliza para asignarle a ese campo un estilo CSS.

El interfaz de usuario definido en el archivo FXML anterior se vería más o menos así una vez ejecutado:

![ud06_javafx_fxml_01.png](/img/user/adjuntos/1DAM_Programacion/Unidad_06/ud06_javafx_fxml_01.png)

Ten en cuenta que también se puede crear ese interfaz **sin usar FXML**, solo que es más engorroso: hay que crear el contenedor y luego ir agregándole los nodos uno a uno. Por ejemplo:

```java
VBox vbox = new VBox();
Button button1 = new Button("Botón 1");
Button button2 = new Button("Botón 2");
vbox.getChildren().add(button1);
vbox.getChildren().add(button2);
```

Sin embargo, hay situaciones donde esto puede ser lo más conveniente. Por ejemplo, si necesitamos crear un nodo del interfaz en tiempo de ejecución (para que aparezca, digamos, un campo de texto nuevo donde antes no había nada). Otro caso habitual es que necesitemos crear muchos nodos semejantes como, por ejemplo, cien campos de texto. Es más fácil entonces crearlos desde Java mediante un bucle que definir los cien elementos en el archivo FXML.

## 4.3. El controlador

Un controlador es una clase que se utiliza para manejar la lógica de la aplicación y la interacción de la interfaz de usuario definida en un archivo FXML. 

La principal responsabilidad de un controlador es **responder a eventos de usuario y realizar acciones en respuesta a esos eventos**.

El controlador para nuestra tabla de multiplicar puede ser más o menos así:

```java
import javafx.fxml.FXML;
import javafx.scene.control.Label;
import javafx.scene.control.TextField;

public class MultiplicationTableController {

    @FXML
    Label resultLabel;
    
    @FXML
    TextField numberInput;

    public void initialize() {
       // Método optativo.
       // Se usa si hay que inicializar algún nodo del interfaz.
       // (Por ejemplo, poner algún valor por defecto en alguna parte
       //  o cargar alguna imagen)
    }

    @FXML
    private void showTable() throws IOException {
        String tabla = "";
        int n = Integer.parseInt(numberInput .getText());
        for (int i = 1; i <= 10; i++) {
            tabla += n + " x " + i + " = " + (n*i) + "\n";
        }
        resultLabel.setText(tabla);
    }
}
```

¿Recuerdas que en el archivo FXML habíamos creado un botón y, en el atributo **`onAction`**, habíamos escrito `#showTable`? Pues bien, ese método **`showTable()`** tiene que existir en el controlador: es lo que se ejecutará al hacer clic en el botón.

También puede haber, **optativamente**, un método **`initialize()`**. Este método se ejecutará automáticamente después de cargar todos los componentes del archivo FXML. Suele usarse para inicializar elementos del interfaz (por ejemplo, para insertar una imagen en un nodo de tipo `ImageView`)

Además, aparecen dos atributos, **`resultLabel`** y **`numberInput`**, que coinciden exactamente en nombre y tipo con los campos definidos en el archivo FXML. De ese modo, nuestro controlador puede acceder a esa etiqueta y ese campo de texto y consultar sus propiedades o manipularlas.

Cada elemento del interfaz tiene un conjunto de métodos diferente para manipularlos. Por ejemplo, los nodos de tipo **`Label`** tienen un método **`setText()`** que permite modificar el texto que contienen, y los nodos de tipo **`TextField`** tienen un método **`getText()`** para consultar el texto que hay escrito en ellos. Esos son los dos métodos de los que se hace uso en este ejemplo.

Observa que, antes de declarar cada elemento de los que aparecen en el archivo FXML, en el controlador aparece la directiva **`@FXML`**. Esto es necesario para que el compilador de Java enlace correctamente los elementos definidos en el archivo FXML con los objetos del controlador.

No olvides que, para que todo funcione, hay que realizar los **`import`** correspondientes.

## 4.4. Modelo y vistas

Aunque JavaFX no impone una estructura de modelo-vista-controlador (MVC) estricta, muchos desarrolladores eligen seguir un diseño MVC.

En este diseño, el **modelo** es la clase donde se integra la lógica de la aplicación. Cosas como el acceso a ficheros, el acceso a bases de datos o las soluciones algorítmicas que tu aplicación requiera, suelen encontrar un buen acomodo en el modelo.

El ejemplo de la tabla de multiplicar es demasiado simple como para necesitar un modelo. Sin embargo, podíamos haber forzado las cosas para que la generación de la tabla de multiplicar, por ejemplo, se hicieran en una clase diferente del controlador. El controlador invocaría a esa clase para realizar los cálculos, recibiría los resultados y los enviaría al interfaz gráfico para mostrarlos.

Las **vistas** son los elementos visuales de la interfaz de usuario. Cualquier aplicación gráfica debe tener, al menos, una vista. Aunque pueden definirse con código Java, lo más cómodo con JavaFX es hacerlo en archivos FXML como el que hemos visto antes. Necesitarás un archivo FXML para cada vista de tu aplicación.

## 4.5. CSS (opcional)

El CSS, como en las páginas web, permite modificar fácilmente la apariencia de los componentes del interfaz. La ventaja de usar CSS es que es un lenguaje de estilo muy extendido y que casi todos los programadores conocen. Aunque el CSS de JavaFX no es exactamente CSS2.1 ni CSS3, se parece bastante.

El archivo o archivos con los estilos se ubica en `./src/main/resources`. Por ejemplo, `./src/main/resources/styles.css`

Dentro de ese archivo podríamos, por ejemplo, definir una reglas de estilo para los componentes del archivo FXML que pertenezcan a la clase `result-label`:

```css
.result-label {
    -fx-font-size: 14pt;
    -fx-text-fill: green;
}
```

Observa que hemos utilizado *selectores de clase*, como **.result-label**, para aplicar nuestro estilo, igual que en CSS convencional. También pueden usarse *selectores de id* (con \#) y *pseudoclases* (con :).

Si revisas el archivo FXML que aparece más arriba, verás que hay un elemento del interfaz con un atributo **styleClass="result-label"**. En concreto, el Label donde se muestra la tabla de multiplicar:

 `<Label fx:id="resultLabel" styleClass="result-label"/>`

Para que el archivo CSS se cargue correctamente, hay que indicarlo en el contenedor primario del archivo FXML. En el ejemplo anterior, lo haríamos así:

`<VBox stylesheets="styles.css" resto-de-atributos-del-vbox>`

Las reglas de estilo del CSS de JavaFX son semejantes a las del CSS convencional, pero no iguales. Aquí te dejo algunas de las más habituales:

- **`-fx-background-color`**: Define el color de fondo del elemento.
- **`-fx-control-inner-background`**: Lo mismo que el anterior (si el otro no funciona).
- **`-fx-text-fill`**: Define el color del texto.
- **`-fx-font-size`**: Define el tamaño de la fuente.
- **`-fx-font-family`**: Define la familia de la fuente.
- **`-fx-padding`**: Define el espacio entre el contenido del elemento y sus bordes.
- **`-fx-border-color`**: Define el color del borde.
- **`-fx-border-width`**: Define el ancho del borde.
- **`-fx-font-weight: bold;`**  Pone el texto en negrita.
- **`-fx-font-style: italic;`**  Pone el texto en cursiva.
- **`-fx-alignment: CENTER;`**  Alinea el texto al centro (también admite los valores `LEFT`, `RIGHT`, `TOP`, `BOTTOM`, y combinaciones de ellos, como `TOP_CENTER`)

## 4.6. Eventos y Listeners

JavaFX, como Swing, utiliza un sistema de eventos para manejar la interacción del usuario. Se pueden asociar métodos en el controlador con eventos en la interfaz de usuario, como clics de botón o cambios en campos de texto.

En el ejemplo de la tabla de multiplicar hay un **evento** (**clic**) y su correspondiente **`listener`** (método **`showTable()`** de la clase controladora)

Este método se ejecutará cuando se produzca el evento clic sobre el objeto adecuado. En este caso, el método obtiene el número introducido por el usuario, genera la tabla de multiplicar correspondiente y actualiza la interfaz de usuario con el resultado (ver código más arriba).
