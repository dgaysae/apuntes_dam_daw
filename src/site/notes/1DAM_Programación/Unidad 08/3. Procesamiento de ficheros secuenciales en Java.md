En este apartado vamos a estudiar la **implementación en Java** de los algoritmos que habitualmente se utilizan para procesar los ficheros secuenciales. 

## 3.1. Escritura

Los registros, en un fichero secuencial, **se añaden siempre al final**. 

Una vez abierto un fichero, se usan **sucesivas llamadas al método de escritura** para insertar los datos (si el fichero es binario) o los caracteres (si es de texto). Ten en cuenta que los datos **se grabarán en el fichero exactamente en el mismo orden** **en el que los escribas**.

Las clases que debes usar dependen de la naturaleza del problema y de las preferencias del programador, pero recuerda que, en general:

* **`FileOutputStream`** y **`FileInputStream`** sirven para E/S **binaria** sencilla (flujos de bytes). Si deseas escribir registros complejos, puedes usarla también, formateando los registros como colecciones de bytes, pero es más cómo optar por usarlas conjuntamente con **`DataOutputStream`** y **`DataInputStream`** (E/S de tipos primitivos) o con **`ObjectOutputStream`** y **`ObjectInputStream`** (serialización de objetos)

* **`FileWriter`** y **`FileReader`** sirven para E/S de caracteres.

* Finalmente, la clase **`File`** sirve de apoyo a todas ellas (todos los flujos pueden crearse a partir de un `File`), y para operaciones con ficheros y directorios (crear, borrar, renombrar, etc)

Para escribir los datos usaremos siempre el método `write()` de la clase correspondiente, por ejemplo:

* **`write(byte b)`** (si usamos `FileOutputStream`)

* **`write(String s)`** (si usamos `FileWriter`)

Estos métodos añaden la información a continuación del último dato escrito, es decir, en forma secuencial. 

## 3.2. Lectura

Cuando se abre un fichero secuencial, el **cursor de lectura** se sitúa siempre **en el primer byte** del fichero.

**Cada vez que se lea un dato, el cursor de lectura se desplaza** automáticamente tantos bytes adelante como se hayan leído. Las lecturas se pueden continuar haciendo **hasta que se alcance el final del fichero**.

Por eso, la lectura de ficheros secuenciales suele aparecer como **un bucle** en el que la condición de salida es haber alcanzado el **fin de fichero**. 

Para comprobar el fin de fichero podemos usar el método available(), si está disponible en nuestra clase (nos dirá cuántos bytes restan por leer en el fichero), o comprobar el valor devuelto por read(), que será ## 3.-1 o null en caso de haber llegado al EOF, como en este ejemplo:

```java
...
    fis = new FileInputStream(file);
    byte content;
    while ((content = fis.read()) != -1) {
        System.out.println((char)content);
    } 
...
```

## 3.3. Búsqueda

En un fichero secuencial **el único método de búsqueda posible es el secuencial**, es decir, que hay que **leer todos los registros**, partiendo del primero, hasta encontrar el que buscamos.

En el siguiente fragmento recorreremos un fichero de forma secuencial buscando el carácter “X” mayúscula. Si lo encontramos, diremos en qué posición del fichero se encuentra su primera ocurrencia y terminaremos.

Observa que, cuando el carácter no se encuentra, **es necesario recorrer todo el fichero** antes de determinar que el dato no está en el mismo. Este es un problema de la búsqueda secuencial.

```java
...
    fis = new FileInputStream(file); 
    byte content; 
    int pos = 0; 
    boolean encontrado = false; 
    while (((content = fis.read()) != -1)) && (!encontrado)) {
        if ((char)content == "X") {
            encontrado = true;
        }
        pos++; 
    }
    
    if (encontrado) {
        System.out.println("Hemos encontrado el carácter X"); 
        System.out.println("Posición: " + pos); 
    }
    else
        System.out.println("El carácter X no está en este fichero");
...
```

## 3.4. Borrado

El borrado (de registros dentro del fichero, no de ficheros completos) es una **operación problemática** en ficheros secuenciales. 

Lo habitual es **reconstruir el fichero por completo**, prescindiendo del dato que se quiere borrar. Es decir:

* **Crear un segundo fichero** secuencial.

* **Copiar en nuevo fichero todos los registros** del fichero original **excepto el que se pretende borrar**.

* **Borrar el fichero original** 

* **Renombrar el fichero nuevo** con el nombre que tenía el original

Como puedes imaginarte, este método, aunque funciona, **es muy lento**, sobre todo si el fichero es largo, por lo que es poco aconsejable usar acceso secuencial si se van a producir borrados de datos con frecuencia.

## 3.5. Modificación

En los ficheros secuenciales sólo puede escribirse al final del fichero. Por lo tanto, para modificar un registro hay que actuar de forma similar al primer método de borrado: **creando un segundo fichero** en el que se **copiarán todos los registros** exactamente igual que en el fichero original, **excepto el que se pretende cambiar**.

Para hacer una modificación directamente sobre los datos existentes necesitamos acceso directo y no solo secuencial.
