Kotlin, al igual que Java, contempla el paradigma de <abbr title="Programación Orientada a Objetos">POO</abbr>. Por tanto, permite encapsular en objetos tanto su **estado** (valor de las propiedades) como su **funcionalidad** (métodos o funciones).

La POO es, conceptualmente, la misma que en Java. Cambian las formas. Así que ¡manos a la obra!


## 1.1. Declarando clases

A diferencia de Java, Kotlin unifica la **declaración de la clase** con su **constructor principal** en una sola línea. En otras palabras, Kotlin permite declarar una clase con parámetros:

```kotlin
class Persona(val nombre: String, var edad: Int)

fun main() {
    var p = Persona("Telmo", 33)
    println(p.nombre)
}
```

Observa que a la hora de instanciar objetos (como `p`), no es necesaria la palabra reservada `new`.

> [!info]  
> En las primeras versiones de Kotlin el constructor se indicaba con la misma palabra clave. En el caso anterior, sería:
> ```kotlin
> class Persona constructor(val nombre: String, var edad: Int)
> ```
> En la actualidad la palabra clave `constructor` no es necesaria.

Cuyo equivalente en Java sería:

```java
class Persona {
    public final String nombre; 
    public int edad;
    
    public Persona(String nombre, int edad) {
        this.nombre = nombre;
        this.edad = edad;
    }
}

public class Main {
	public static void main(String[] args) {
	    Persona p = new Persona("Telmo", 33);
		System.out.println(p.nombre);
	}
}
```

### Constructor principal, propiedades y funciones miembro

En los ejemplos anteriores se ve cómo Kotlin permite definir un **constructor principal** en la cabecera de la clase, de forma similar a como se definen los parámetros de una función. Los parámetros son las **propiedades** de dicha clase que serán visibles desde dicho constructor, donde **`nombre` es una costante** (inmutable) y **`edad` es una variable** (mutable).

> [!warning] Importante 
> Los **parámetros del constructor principal** que sean propiedades de la clase **deben llevar la palabra clave `val` o `var`**. De lo contrario, son solo parámetros que no formarán parte del estado de los objetos de esa clase. En tal caso deben asignarse a una propiedad o usarse en alguna función miembro.

Como se puede observar, las propiedades son públicas por defecto, al igual que las funciones miembro. Es más, **en Kotlin todo es público mientras no se especifique lo contrario**.

Si queremos que algunas propiedades sean privadas, es decir, que sean visibles sólo por la clase e invisible para el resto, se añade el `private` al principio de la declaración:

```kotlin
class Motor {
    // 1. Propiedad privada INMUTABLE
    private val numeroDeSerie: String = "MOT-2026-XYZ"

    // 2. Propiedad privada MUTABLE (invisible desde el exterior de la clase)
    private var temperatura: Int = 20

    fun arrancar() {
        temperatura = 90 // La propia clase puede modificarla
        println("Motor encendido. Número de serie: $numeroDeSerie")
    }

    fun mostrarEstado() {
        println("Temperatura actual: $temperatura°C")
    }
}

fun main() {
    val miMotor = Motor()
    
    miMotor.arrancar()
    miMotor.mostrarEstado()

    // miMotor.temperatura = 100 
    // ❌ ERROR: No es accesible desde fuera de la clase

    // miMotor.numeroDeSerie = "OTRO-123" 
    // ❌ ERROR: Es privada y además es una constante (val)
}

```

También se pueden definir las **propiedades dentro de la clase**. Al no estar en el constructor principal, **no son estrictamente necesarias para la instanciación de objetos**. En el siguiente caso, tenemos las propiedades `nombre` y `edad` en el constructor principal y `matriculado` y `expediente` declaradas dentro de la clase:

```kotlin
class Persona(val nombre: String, var edad: Int) {
    var matriculado: Boolean = false
    var expediente: String? = null
}

fun main() {
    val personaFake = Persona()  // ❌ Error! nombre y edad obligatorios
    val p = Persona("Telmo", 33) // Instancia de objeto Persona sin new
    
    // Estado del objeto p:
    println(p.nombre)      // Temo
    println(p.edad)        // 33 
    println(p.matriculado) // false
    println(p.expediente)  // null
}
```

Podemos añadir las **funciones miembro** (**métodos** en Java) que creamos oportunas. Como `printInfo`, que hará uso de todas las propiedades: 

```kotlin
class Persona(val nombre: String, var edad: Int) {
    var matriculado: Boolean = false
    var expediente: String? = null
    
    fun printInfo() {
        if (matriculado)
        	println("$nombre, de $edad de edad, tiene la matrícula registrada")
        else
        	println("$nombre, de $edad de edad, no se ha matriculado")
        
        println(expediente?.let {
            "Su expediente: $expediente"
        } ?:run {
            "No hay expediente registrado"
        })
    }
}

fun main() {
    val p = Persona("Telmo", 33)
    p.printInfo()
    println("---------------------------")
    p.expediente = "Expediente de Telmo" // propiedades públicas por defecto
    p.printInfo()
}
```

### `getters` y `setters`

**Un `setter`** funciona de forma distinta en Kotlin, ya que va asociado directamente a su propiedad. Un setter no es una función aparte. Se declara inmediatamente debajo de la propiedad de la siguiente forma:

```kotlin
class Clase(val propiedad1: String) {
    var propiedad2: Int = 0
        [private] set([value]) {
            field = if (value < 0) ? 0 else value
        }
}
```

### Bloque de inicialización - `init`

Ya hemos visto que el constructor principal equivale al estańdar de Java para inicializar las propiedades. Nada más. Pero ¿y si queremos hacer un constructor más complejo que el anterior, donde haya más lógica como valicaciones, etc?

Imaginemos que queremos hacer lo que se hace en este código de Java para validar que la edad no sea negativa:

```java
class Persona {
    public final String nombre; 
    public int edad;
    
    public Persona(String nombre, int edad) {
        this.nombre = nombre;
        this.edad = (edad < 0) ? 0 : edad;  // validamos la edad
    }
}
```

El constructor principal, tal y como está planteado, no puede albergar código. Para darle lógica hay usar el bloque `init`:

```kotlin
class Persona(val nombre: String, var edad: Int) {
    init {
        edad = if (edad < 0) 0 else edad
    }
}
```

El bloque de inicialización **`init` contiene la lógica del constructor principal**, pero **se ejecuta después de él**. Es decir, primero se inicializan las propiedades indicadas en el constructor principal y después se ejecuta `init`.
