Un `enum` es una **clase especial**, un tipo de datos que representa un **conjunto de valores constantes e inmutables**. Se utiliza cuando conocemos de antemano todos los valores posibles que puede tomar una variable.

**Ejemplos típicos en DAM:**

- Estados de una petición de red: `LOADING`, `SUCCESS`, `ERROR`.
- Roles de un usuario: `ADMIN`, `PREMIUM`, `GUEST`.
- Tipos de pago: `TARJETA`, `PAYPAL`, `BIZUM`.

En Kotlin, se definen usando dos palabras reservadas juntas: **`enum class`**.

kotlin

```
enum class EstadoPedido {
    PENDIENTE,
    ENVIADO,
    ENTREGADO,
    CANCELADO
}
```

2. Enums con Propiedades y Métodos (Constructores)

A diferencia de otros lenguajes donde un enum es solo una lista de etiquetas, en Kotlin cada constante es una **instancia de la clase**. Esto significa que puedes pasarle parámetros a su constructor y asociarles datos o comportamientos.

kotlin

```
enum class TipoUsuario(val prioridad: Int, val accesoTotal: Boolean) {
    ADMIN(1, true),
    EDITOR(2, false),
    GUEST(3, false); // <- ¡Ojo! Si añades métodos abajo, este punto y coma es OBLIGATORIO

    // Podemos añadir funciones dentro del enum
    fun mostrarInfo() = "Rol: $name (Prioridad: $prioridad)"
}
```

3. El match perfecto: `enum` + `when` (Pregunta de examen)

El uso más potente de los enums en Kotlin es combinarlo con la estructura **`when`** (el sustituto mejorado del `switch` de Java).

Si usas `when` como una expresión (para asignar un valor) con un `enum`, **Kotlin te obliga a controlar todos los casos posibles**. Si te dejas uno, el compilador dará error. Esto evita que olvides gestionar estados nuevos.

kotlin

```
val estadoActual = EstadoPedido.ENVIADO

// El compilador verifica que PENDIENTE, ENVIADO, ENTREGADO y CANCELADO estén cubiertos
val mensajeAlerta = when (estadoActual) {
    EstadoPedido.PENDIENTE -> "El almacén está preparando tu paquete."
    EstadoPedido.ENVIADO   -> "El repartidor está en camino."
    EstadoPedido.ENTREGADO -> "Paquete recibido correctamente."
    EstadoPedido.CANCELADO -> "El pedido ha sido anulado."
    // 💡 ¡No hace falta poner un "else"! Al ser un enum, Kotlin ya sabe que no hay más opciones.
}
```

4. Propiedades y Métodos Nativos de los Enums

Cada constante de un enum incluye de forma automática dos propiedades muy útiles:

- **`name`:** Devuelve el nombre exacto de la constante en formato `String`.
- **`ordinal`:** Devuelve la posición de la constante (empezando desde `0`).

kotlin

```
val miEstado = EstadoPedido.ENTREGADO

println(miEstado.name)    // Imprime: "ENTREGADO"
println(miEstado.ordinal) // Imprime: 2 (PENDIENTE=0, ENVIADO=1, ENTREGADO=2)
```

Usa el código con precaución.

Buscar y listar constantes

- **`entries`:** Devuelve una lista con todas las constantes del enum (es la alternativa moderna y eficiente al antiguo `.values()`).
- **`valueOf(String)`:** Convierte un texto en la constante del enum que coincida (lanza error si no existe).

kotlin

```
// 1. Recorrer todos los valores posibles
for (estado in EstadoPedido.entries) {
    println("Disponible: ${estado.name}")
}

// 2. Convertir un String que viene de una Base de Datos o API a Enum
val estadoDesdeBackend = "CANCELADO"
val estadoEnum = EstadoPedido.valueOf(estadoDesdeBackend) // Devuelve EstadoPedido.CANCELADO
```

5. Conexión total: `enum` + `JSON` (`@Serializable`)

Cuando trabajas con **Kotlinx Serialization**, puedes serializar y deserializar enums directamente de forma nativa.

Si tu JSON devuelve `"ADMIN"`, la librería lo mapeará automáticamente a `TipoUsuario.ADMIN`. ¿Y si el JSON usa minúsculas o códigos extraños? Usamos la anotación `@SerialName`:

kotlin

```
import kotlinx.serialization.Serializable
import kotlinx.serialization.SerialName

@Serializable
enum class EstadoSuscripcion {
    @SerialName("active") ACTIVA,
    @SerialName("expired") EXPIRADA,
    @SerialName("pending_payment") PAGO_PENDIENTE
}
```

6. Comparativa rápida: ¿Cuándo usar `enum class` vs `sealed class`?

Esta es la típica pregunta trampa para pillar a alumnos de 2º de DAM:

- **Usa `enum class`** si tus constantes son **estrictamente fijas y no necesitan almacenar datos dinámicos diferentes entre sí** (por ejemplo, todos los usuarios tienen un entero `prioridad`, solo cambia el valor).
- **Usa `sealed class` (clases selladas)** si cada estado necesita **datos completamente distintos**. _(Ejemplo: El estado `SUCCESS` necesita una lista de datos de la API, pero el estado `ERROR` necesita un `String` con el mensaje de error y un `Int` con el código HTTP)_.
