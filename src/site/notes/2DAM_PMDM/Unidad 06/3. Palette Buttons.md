## 3.1. Introducción

Los botones son los controles visuales habituales para que permitir al usuario lanzar una acción: enviar los datos de un formulario, (des)activar alguna funcionalidad, etc.

En el XML de las *activities* de Android podemos definir botones de dos formas:

1. Insertando el botón desde la paleta, lo que generaría un componente `Button` estándar:
  ```xml
  <Button
      android:layout_width="wrap_content"
      android:layout_height="wrap_content"
      android:text="Aceptar" />
  ```

2. Haciéndolo manualmente en el XML para introducir un **botón personalizado**:
  ```xml
  <android.widget.Button
      android:layout_width="wrap_content"
      android:layout_height="wrap_content"
      android:background="@drawable/my_custom_shape"
      android:text="Aceptar" />
  ```

El primer caso presenta muchas limitaciones, ya que mostrará un botón estándar de Android y muchas de las propiedades no funcionarán para él (ya que se salen del estándar del botón).

Es el segundo caso, el personalizado, el que nos permitirá crear formas personalizadas con estilos propios en la carpeta **`drawable`** del proyecto Android. Estas formas pueden ir desde rectángulos con esquinas redondeadas hasta formas más complejas utilizando herramientas de diseño vectorial.

Ya que los botones estándar no ofrecen muchas opciones, en este documento nos centraremos en los **botones personalizados**.

## 3.2. Botones personalizados

### 3.2.1. Dar forma a los botones

Como hemos indicado anteriormente, para crear formas personalizadas o ***ShapeDrawables*** para los botones hemos de crear recursos vectoriales dentro de nuestra carpeta de recursos (res/drawable). Para ello, crearemos un nuevo ***drawable resource file***. Al hacerlo, veremos un nuevo fichero XML con la forma siguiente:

```xml
<selector xmlns:android="http://schemas.android.com/apk/res/android">

</selector>
```

#### Rectángulos

El **selector** permite combinar diferentes *drawables* para crear efectos visuales más complejos. En este **selector** vamos a definir la forma de nuestro botón mediante un **ítem** que contendrá una figura (**`shape`**). Creamos un fichero **`rectangulo.xml`** con el siguiente contenido:  

```xml
<selector xmlns:android="http://schemas.android.com/apk/res/android">
    <item>
        <shape android:shape="rectangle">
            <corners android:radius="10dp" />
            <!--
            <solid android:color="#FF0000" />
            -->
            <gradient android:startColor="@color/black"
                      android:centerColor="@color/gray"
                      android:endColor="@color/green" />
        </shape>
    </item>
</selector>
```

En el ejemplo hemos definido un rectángulo y dentro de él definimos el redondeo de las esquinas (**radius**) y el **color** de relleno.

Hemos usado las propiedades **corners** y **solid**, pero hay muchas más propiedades (size, etc.) que habría que explorar.

Por ejemplo, en lugar de un color uniforme, si queremos aplicar un gradiente:  

```xml
<selector xmlns:android="http://schemas.android.com/apk/res/android">
    <item>
        <shape android:shape="rectangle">
            <corners android:radius="10dp" />
            <gradient android:startColor="@color/black"
                      android:centerColor="@color/gray"
                      android:endColor="@color/green"
                      android:angle="90" />
        </shape>
    </item>
</selector>
```

Aquí indicamos el color de inicio y fin del gradiente, además del color que aparecerá en el centro. Además, se le indica el ángulo (90º) o dirección del gradiente.

#### Óvalos

Otro ejemplo podría ser el de un óvalo. Creamos un fichero **ovalo.xml** con el siguiente contenido:  

```xml
<selector xmlns:android="http://schemas.android.com/apk/res/android">
    <item>
        <shape android:shape="oval">
            <size android:width="100dp"
                  android:height="100dp" />
            <solid android:color="@color/orange" />
        </shape>
    </item>
</selector>
```

### 3.2.2. Aplicar formas a un botón

Una vez creada la forma personaliza que queremos, ahora sólo hay que aplicar al botón correspondiente. Para ello, vamos al XML de la activity y la asignamos en la propiedad **`background`** del botón:  

```xml
<android.widget.Button
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:background="@drawable/ovalo"
    android:text="Mi Botón" />
```

**`@drawable/ovalo`** hace referencia al archivo XML donde se ha definido la forma en la carpeta **`drawable`**.

> [!warning] Ojo 
> No se debe olvidar que para personalizar un botón no se debe hacer sobre el botón estándar (`Button`), sino sobre **`android.widget.Button`**.

> [!info]  
> Si usamos la propiedad `background` para aplicar la forma personalizada, aún tenemos la opción de cambiar el color de fondo de dicha forma desde el botón usando la propiedad **`backgroudTint`**.

### 3.2.3. StateListDrawable

Para crear diferentes estados para un botón (presionado, enfocado, etc.) se utiliza **`StateListDrawable`**. Veamos un ejemplo:

```xml
<selector xmlns:android="http://schemas.android.com/apk/res/android">
    <item android:state_pressed="true"
          android:drawable="@drawable/button_pressed" />
    <item android:drawable="@drawable/button_normal" />
</selector>  
```

De esta manera podemos establecer unos estilos para determinadas condiciones del estado del control (en este caso, presionado o no).

## 3.3. ImageButton

Son botones **sin texto**. Simplemente se le asigna una imagen de las disponibles en **`mipmap`** o **`drawable`**.

## 3.4. ChipGroup / Chip

Un ChipGroup muestra un grupo de botones como el de la figura[^1] donde cada botón es un control **`Chip`**:  

![ud06_pmdm_04.png\|300](/img/user/adjuntos/2DAM_PMDM/Unidad_06/ud06_pmdm_04.png)

### 3.4.1. ChipGroup

El [**`ChipGroup`**](https://developer.android.com/reference/com/google/android/material/chip/ChipGroup) como tal es un mero contenedor que agrupa varios `Chips` y los muestra de forma organizada, pero puede configurarse para mostrarlos en una o varias líneas, permitir la selección de uno o varios `Chips`, etc.

Para crear un estilo que afecte a todos los `Chips` de un `ChipGroups` debemos crear dicho estilo en nuestros recursos, ya sea en **`res/values/themes/themes.xml`** o en **`styles.xml`**.

Sea donde fuere, se puede crear un estilo de la siguiente manera:  

```xml
<style name="MyChipStyle">
    <item name="android:textColor">@color/white</item>
    <item name="android:textStyle">bold</item>
    <item name="android:textSize">14sp</item>
    <item name="chipBackgroundColor">@color/blue</item>
    <item name="chipStrokeColor">@color/gray</item>
    <item name="chipStrokeWidth">2dp</item>
</style>
```

Una vez creado e identificado con el nombre **`MyChipStyle`** podemos aplicarlo al `ChipGroups`, en el layout donde se encuentre:  

```xml
<com.google.android.material.chip.ChipGroup
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    app:chipSpacingHorizontal="8dp"
    app:chipSpacingVertical="4dp"
    app:singleLine="false">
    
    <com.google.android.material.chip.Chip
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        style="@style/MyChipStyle"
        android:text="Chip 1" />

   </com.google.android.material.chip.ChipGroup>
```

También podríamos hacerlo para [determinadas casuísticas](https://howtodoandroid.com/android-chips-material-component/) de los Chips, por ejemplo para **`Entry`[^2]**:  

```xml
<style name="MyChipStyle"
       parent="Widget.MaterialComponents.Chip.Entry">
    <item name="android:textColor">@color/white</item>
    <item name="android:textStyle">bold</item>
    <item name="android:textSize">14sp</item>
    <item name="chipBackgroundColor">@color/blue</item>
    <item name="chipStrokeColor">@color/gray</item>
    <item name="chipStrokeWidth">2dp</item>
</style>
```

Y luego se aplicarían de la misma forma a los distintos `Chips`.

### 3.4.2. Chip

Los **`Chips`** son elementos de interfaz de usuario que representan una pequeña pieza de información, como una etiqueta, un filtro o una acción. Los **`ChipGroups`** son contenedores que agrupan varios `Chips`, proporcionando una forma organizada de presentar múltiples opciones al usuario.

Podemos incluir elementos gráficos (iconos) para personalizar los `Chips`:  

```xml
<com.google.android.material.chip.ChipGroup
    . . .>
    
    <com.google.android.material.chip.Chip
        android:layout_width="wrap_content" />
        android:layout_height="wrap_content" />
        style="@style/MyChipStyle"
        app:chipIcon="@drawable/MyIcon"
        android:text="Chip 1" />

   </com.google.android.material.chip.ChipGroup>
```

Podemos ampliar los estilos para nuestros `Chips`. Por ejemplo, si el `Chip` está pulsado queremos que su texto tenga un color y, en caso contrario, otro distinto. Esto lo podemos hacer directamente en el estilo que hemos creado antes (**`MyChipStyle`**) o creando un nuevo ***drawable resource file*** independientes en un **`StateListDrawable`**, por si esta cualidad la quiero reutilizar en otras partes de mi proyecto. Ese fichero podría ser **`chip_textcolor.xml`**:

Al hacerlo, veremos un nuevo fichero XML con la forma siguiente:  

```xml
<selector xmlns:android="http://schemas.android.com/apk/res/android">
    <item android:color="@color/white"
          android:state_checked="true" />
    <item android:color="@color/black"
          android:state_checked="false" />
</selector>
```

Esta condición que indica que el texto sea **blanco** si el elemento (sea el que sea, no sólo el Chip) está **seleccionado** o negro en caso contrario, la aplicamos en el estilo de nuestro Chip:  
```xml
<style name="MyChipStyle"
       parent="Widget.MaterialComponents.Chip.Entry">
    <item name="android:textColor">@style/chip_textcolor</item>
    <item name="android:textStyle">bold</item>
    <item name="android:textSize">14sp</item>
    <item name="chipBackgroundColor">@color/blue</item>
    <item name="chipStrokeColor">@color/gray</item>
    <item name="chipStrokeWidth">2dp</item>
</style>
```

### 3.4.3. Código

#### Acceso/Recorrido de Chips

Si queremos recorrer todos los `Chips` de un `ChipGroup`, en este caso para desmarcarlos:

```kotlin
for (i in 0 until chipGroup.childCount) {
    val chip = chipGroup.getChildAt(i) as Chip
    chip.isChecked = false
    
    chip.setOnCloseIconClickListener {
        chipGroup.removeView(it)
    }
    
    chip.setOnClickListener {
        val chipAux = it as Chip
        Toast.makeText(this,
                       "Se ha pulsado ${chipAux.text}",
                       Toast.LENGTH_SHORT).show()
    }
}
```

> [!warning] Ojo 
> Es importante reseñar el **casting** que se hace en el código (`as Chip`), ya que el método `getChildAt` devuelve un objeto de tipo `View`, que obviamente no tiene todas las propiedades de un `Chip`.

Además se han creado los callbacks para implementar dos eventos:

- `setOnCloseIconClickListener`: cuando se pulsa el aspa del `Chip`, que recordemos que lo tiene al ser de tipo `Entry`.

- `setOnClickListener`: cuando se pulsa el `Chip`.

> [!info] 
> También indicar que en los contextos de ambos callbacks, el objeto que se maneja (entrada del lambda) es el objeto, que se representa con el identificador **`it`** y es de tipo `View`.

#### Crear y añadir Chip a ChipGroup

Veamos un ejemplo para ver cómo crear un `Chip` en Kotlin, agregarlo a un `ChipGroup`, personalizarlo y manejar el evento de cierre:

```kotlin
val chipNuevo = Chip(this)
chipNuevo.text = "Nuevo Chip"
chipNuevo.chipIcon = resources.getDrawable(R.drawable.ic_favorite, null)
chipNuevo.isChipIconVisible = true
chipNuevo.isCloseIconVisible = true
chipNuevo.isClickable = true

chipGroup.addView(chipNuevo as View)
chipNuevo.setOnCloseIconClickListener {
        chipGroup.removeView(it)
        // Otra alternativa
        // chipGroup.removeView(chipNuevo as View)
    }
```

## 3.5. RadioGroup / RadioButton

Estos dos componentes trabajan en conjunto para ofrecer una forma de seleccionar una única opción de entre varias. Este control permite al usuario **elegir sólo una** de las opciones mostradas.

Imagina un formulario donde el usuario debe seleccionar su género: “Hombre”,  “Mujer”, “Otra identidad sexual” y “Sin especificar”. Aquí es donde entran en juego estos elementos.

![ud06_pmdm_05.png](/img/user/adjuntos/2DAM_PMDM/Unidad_06/ud06_pmdm_05.png)

Veamos cómo quedaría el RadioGroup con los RadioButtons correspondientes a este ejemplo:  

```xml
<RadioGroup
    android:id="@+id/rgGenero"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:orientation="vertical">

    <RadioButton
        android:id="@+id/rbHombre"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Hombre" />

    <RadioButton
        android:id="@+id/rbMujer"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Mujer" />

    <RadioButton
        android:id="@+id/rbOtra"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Otra identidad sexual" />

    <RadioButton
        android:id="@+id/rbSinEspecificar"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Sin especificar"
        android:checked=true
        android:buttonTint="@color/blue"/>

</RadioGroup>
```

En este ejemplo podemos ver varios atributos útiles:

| Propiedad | Descripción |
| :---- | :---- |
| `buttonTint` | Da un color al radiobutton. |
| `checked` | Indica si el radiobutton debe aparecer seleccionado. Aunque se pueden marcar todos los radiobuttons en un radiogroup, sólo quedará marcado el último **siempre que** cada radiobutton tenga su correspondiente **id**. |

> [!warning] Importante 
> Si no se indica el id en cada radiobutton, su comportamiento no será el esperado. Esto es, se podrían seleccionar varios radios al mismo tiempo.

### 3.5.1. Código

Veamos cómo obtener el id del `Radiobutton` seleccionado:

```kotlin
val rgGenero = findViewById<RadioGroup>(R.id.rgGenero)
val idRBSeleccionado = rgGenero.checkedRadioButtonId

// Obtener la referencia al RadioButton seleccionado
val rbSeleccionado = findViewById<RadioButton>(idRBSeleccionado)
val selectedText = rbSeleccionado?.text.toString()
```

O podemos marcar por código uno de los `RadioButtons`:

```kotlin
val rgGenero = findViewById<View>(R.id.rgGenero) as RadioGroup
var rbSeleccionar = rgGenero.getChildAt(1) as RadioButton
rgGenero.check(rbSeleccionar.id)
```

> [!info]  
> En el ejemplo anterior se aprecia el uso de `View` y el casting para recuperar el `RadioGroup`. Es importante tener esto en cuenta a la hora de programar y, obviamente, es preferible establecer los controles explícitamente antes que hacer casting.

#### Manejar el evento click

Se puede implementar el evento **`onRadioButtonClick`** tanto desde la vista como por código.

##### 1. Implementar desde la vista
  Desde la vista (XML) es una forma rápida y sencilla de manejar eventos simples, especialmente cuando tienes pocos `RadioButtons` y la lógica a ejecutar es directa.<br>
  Para ello sólo hay que declarar el `RadioGroup` y los `RadioButtons` en tu archivo XML, **asignándole un ID único** a cada `RadioButton` para poder referenciarlo posteriormente.<br>
  Entonces se puede añadir el atributo **`android:onClick:`** a cada `RadioButton`, indicando el método que será llamado cuando se haga clic en él.
```xml
<RadioGroup
    android:id="@+id/rgGenero"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:orientation="vertical">
    <RadioButton
        android:id="@+id/rbHombre"
	    android:layout_width="wrap_content"
	    android:layout_height="wrap_content"
	    android:text="Hombre"
	    android:onClick="onRadioButtonClicked" />
    <RadioButton
	    android:id="@+id/rbMujer"
	    android:layout_width="wrap_content"
	    android:layout_height="wrap_content"
	    android:text="Mujer"
	    android:onClick="onRadioButtonClicked" />
	<RadioButton
	    android:id="@+id/rbOtra"
	    android:layout_width="wrap_content"
	    android:layout_height="wrap_content"
	    android:text="Otra identidad sexual"
	    android:onClick="onRadioButtonClicked" />
    <RadioButton
        android:id="@+id/rbSinEspecificar"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Sin especificar"
        android:checked=true
        android:buttonTint="@color/blue"
        android:onClick="onRadioButtonClicked" />
</RadioGroup>
```

Ahora toda implementar ese método **`onRadioButtonClicked`** en la `Activity`. Es importante dejar claro que **debe ser público** y **recibir un parámetro de tipo View**, ya que automáticamente se envía el `RadioButton` a este método como una `View`. El motivo es que este método puede funcionar para otros controles, por lo que la forma de abarcarlos a todos es enviando un `View`.

Dentro del método, puedes usar el ID de la vista para identificar el `RadioButton` que ha sido seleccionado y realizar las acciones correspondientes.

```kotlin
class MainActivity : AppCompatActivity() {
    // ...
    fun onRadioButtonClicked(view: View) {
        if (view is RadioButton) {
            // Comprobar si está activado
            val checked = view.isChecked
            // Identificamos el radio button que se ha pulsado
            when (view.getId()) {
                R.id.rbHombre -> {
                    if (checked) {
                        // Opción 1 seleccionada
                        Toast.makeText(this, "Ha seleccionado Hombre", Toast.LENGTH_SHORT).show()
                    }
                    // ...
                }
            }
        }
    }
}
```

Se puede apreciar que se comprueba qué control es ese View de entrada. Esto nos permite implementar un método para distintos controles (Chips, RadioButtons, etc.).

Este código se ha dispuesto así con un fin didáctico. La realidad es que no es necesario comprobar si un RadioButton está o no chequeado (lo está porque se ha pulsado sobre él, obviamente).

##### 2. Implementar desde código

Para asignar a un radio group el evento de click en cualquiera de sus elementos, se hará mediante el método `setOnCheckedChangeListener` para registrar un listener que será notificado cuando cambie el estado de selección de un `RadioButton` dentro del grupo.

```kotlin
val radioGroup = findViewById<RadioGroup>(R.id.radioGroup)
radioGroup.setOnCheckedChangeListener { group, checkedId ->
    // checkedId es el ID del RadioButton seleccionado
    when (checkedId) {
        R.id.radioButton1 ->
            // Opción 1 seleccionada
        // ...
    }
}
```

El método anterior puede usarse con varios `RadioGroups`, verificando el ID del `RadioGroup` para determinar cuál ha generado el evento:

```kotlin
radioGroup.setOnCheckedChangeListener { group, checkedId ->
    when (group.id) {
        R.id.radioGroup1 -> {
            // Manejar eventos del RadioGroup1
        }
        R.id.radioGroup2 -> {
            // Manejar eventos del RadioGroup2
        }
    }
}
```


## 3.6. CheckBox

Los `CheckBoxes` son elementos de interfaz de usuario que permiten al usuario seleccionar una o más opciones de un conjunto. A diferencia de los [`RadioButtons`](#radiogroup-/-radiobutton), donde solo se puede seleccionar una opción a la vez, los `CheckBox` permiten seleccionar múltiples opciones de forma independiente.

![ud06_pmdm_06.png](/img/user/adjuntos/2DAM_PMDM/Unidad_06/ud06_pmdm_06.png)

Veamos un ejemplo en la activity:

```xml
<CheckBox android:id="@+id/dbTerminos"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Aceptar términos y condiciones"
    android:onClick="onCheckBoxClicked" />
```

Para establecer el listener:  

```kotlin
class MainActivity : AppCompatActivity() {
    // ...
    fun onRadioButtonClicked(view: View) {
        . . .
    }
    fun onCheckBoxClicked(view: View) {
        if (view is CheckBox) {
            // Comprobar si está activado
            val checked = view.isChecked
            // Identificamos el check que se ha pulsado
            when (view.getId()) {
                R.id.dbTerminos -> {
                    if (checked) {
                        Toast.makeText(this,
                                "Ha aceptado los términos y condiciones",
                                Toast.LENGTH_SHORT).show()
                    }
                    else {
                        Toast.makeText(this,
                                "Rechaza los términos y condiciones",
                                Toast.LENGTH_SHORT).show()
                    }
                    // ...
                }
            }
        }
    }
}
```

## 3.7. ToogleButton

Este control permite al usuario alternar entre dos estados (activo/inactivo, encendido/apagado, on/off, etc.). Es similar a un CheckBox, pero visualmente representa mejor esta idea de alternancia ya que se trata de un botón mantiene su estado. Es decir, si se pulsa, se mantiene pulsado:

![ud06_pmdm_07.png\|300](/img/user/adjuntos/2DAM_PMDM/Unidad_06/ud06_pmdm_07.png)

En la activity:

```xml
<ToggleButton
    android:id="@+id/toggleButton1"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:textOn="On"
    android:textOff="Off" />
```

Dependiendo de si está o no activado, se mostrará el texto de **`textOn`** o **`textOff`** respectivamente.

Para asignarle un listener desde código:

```kotlin
val toggleButton = findViewById<ToggleButton>(R.id.toggleButton1)
toggleButton.setOnCheckedChangeListener { buttonView, isChecked ->
    if (isChecked) {
        // El botón está activado
        Toast.makeText(this, "El botón está activado", Toast.LENGTH_SHORT).show()
    } else {
        // El botón está desactivado
        Toast.makeText(this, "El botón está desactivado", Toast.LENGTH_SHORT).show()
    }
}
```

> [!warning] Cuidado
> Toast se utiliza para estas pruebas como flag, pero no es recomendable abusar de su uso en una aplicación real.

El método para asignar el listener al `ToggleButton` cada vez que se pulsa es el **`setOnCheckedChangeListener`**.

Vemos que se usa una lambda con los parámetros:

* **`buttonView`**: representa el `ToggleButton` que ha cambiado de estado.  
* **`isChecked`**: indica el estado del botón (activado = true; desactivado = false).

## 3.8. Switch

Es similar a un `ToggleButton`, ya que permite al usuario alternar entre dos estados, pero con una apariencia más moderna y una experiencia de usuario más intuitiva.

![ud06_pmdm_08.png\|300](/img/user/adjuntos/2DAM_PMDM/Unidad_06/ud06_pmdm_08.png)

Veamos algunas propiedades:

```xml
<Switch
    android:id="@+id/swNotificaciones"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Notificaciones"
    android:thumb="@drawable/miImagen"
    android:thumbTint="@color/azul"
    android:trackTint="@color/gray" />
```

**`thumb`** te permite sustituir el círculo del botón por un icono propio. **`thumbTint`** cambia el color de dicho icono y **`trackTint`** el color de la barra por la que se desplaza el botón.

> [!warning] Ojo
> Aunque puede resultar atractiva la idea de cambiar el `thumb` de un `Switch`, en general el control es de por sí intuitivo y “usable”, por lo que no se recomienda.

Para asignarle un listener desde código:

```kotlin
val swNotificaciones = findViewById<Switch>(R.id.swNotificaciones)
toggleButton.setOnCheckedChangeListener { buttonView, isChecked ->
    if (isChecked) {
        // El switch está activado
        Toast.makeText(this,
                "El switch está activado",
                Toast.LENGTH_SHORT).show()
    } else {
        // El botón está desactivado
        Toast.makeText(this,
                "El switch está desactivado",
                Toast.LENGTH_SHORT).show()
    }
}
```

## 3.9. FloatingActionButton

El <abbr title="FloatingActionButton">FAB</abbr> es un botón que se coloca flotando sobre la interfaz de usuario, generalmente en la esquina inferior derecha de la pantalla. Su propósito principal es **destacar una acción principal** o una llamada a la acción ([CTA](https://www.doofinder.com/es/blog/call-to-action)) dentro de tu aplicación. Al ser flotante, se mantiene visible incluso cuando el usuario se desplaza por la pantalla, lo que lo hace muy llamativo y fácil de encontrar.

![ud06_pmdm_09.png](/img/user/adjuntos/2DAM_PMDM/Unidad_06/ud06_pmdm_09.png)

Generalmente suele crearse con el atributo **`android:clickable`** aunque, tenga el valor que tenga, el botón se podrá pulsar igualmente:

```xml
<com.google.android.material.floatingactionbutton.FloatingActionButton
    android:id="@+id/fab"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:clickable="true"
    android:layout_gravity="bottom|end"
    android:srcCompat="@drawable/ic_add" />
```

Para asignarle desde código un listener se usa el evento **`setOnClickListener`**, ya visto en otros casos como los [**`Chip`**](#chipgroup-/-chip).

Este control suele crearse para crear un nuevo elemento (p.e. agregar un nuevo contacto, tarea o evento), abrir un menú, abrir otra pantalla de la aplicación, etc.

[^2]:  El `Entry` añade una aspa para permitir eliminar la selección del `Chip`.
