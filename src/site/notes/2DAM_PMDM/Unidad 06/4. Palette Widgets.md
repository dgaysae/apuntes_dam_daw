Los *widgets* son fragmentos de código que ofrecen una pequeña funcionalidad bien definida. De esta forma se evita que funciones comunes y habituales tengan que implementarse continuamente de un proyecto a otro.

Android Studio ofrece algunos widgets, que veremos a continuación.

## 4.1. ImageView
{ #ec8ddb}


Se utiliza para mostrar imágenes en una aplicación. Es como un marco que **solo admite imágenes** para mostrarlas al usuario.

Este widget permite mostrar **imágenes estáticas** de nuestros proyectos almacenadas en los directorios de recursos **`drawable`** o **`mipmap`**. Aunque si el número y tamaño de estas imágenes es elevado, suele ser conveniente cargarlas desde internet. Así nuestra app no ocupa tanto espacio en el dispositivo.

```xml
<ImageView  
    android:id="@+id/imageView"  
    android:layout_width="wrap_content"  
    android:layout_height="wrap_content"  
    android:src="@drawable/mi_imagen" />
```
{ #ddd339}


Su uso va desde una imagen (sea icono, dibujo, o fotografía) en una pantalla hasta una galería de imágenes (usando varias `ImageViews`).

El atributo **`android:src`** especifica una de las imágenes que tengo en mis recursos y que se mostrará en el área del ImageView.

> [!warning] Si vamos a cargar imágenes de Internet... 
> Antes de comenzar con la carga de imágenes hay que saber cómo darle permisos a nuestra app para que acceda a Internet. El motivo es sencillo: las imágenes y demás recursos que vamos a ver de aquí en adelante podrían estar en una web y no en local (en nuestro dispositivo).
> 
> Para ello hay que añadir los permisos de acceso a Internet en el fichero **`AndroidManifest.xml`** del proyecto.
> 
> Los permisos se agregan antes de la etiqueta **`<application ...`** y se añaden en la etiqueta **`uses-permission`**. Este permiso en concreto sería:
> ```xml
> <uses-permission android:name="android.permission.INTERNET" />
> ```
{ #85c065}


En las primeras versiones de Android, cada desarrollador implementaba sus propias funciones para descargar las imágenes de la web. Pero en la actualidad esas labores son menos artesanales y, en su lugar, se utilizan librerías. Eso es lo que vamos a hacer también nosotros.

### 4.1.1. Picasso

Picasso es una biblioteca de Android muy popular que simplifica enormemente la tarea de cargar y mostrar imágenes en nuestras aplicaciones. Se encarga de gestionar tareas como la **descarga** de imágenes de internet, la **gestión del almacenamiento** del almacenamiento de esas imágenes en caché (tanto en memoria como en disco) para evitar descargas redundantes y mejorar el rendimiento de la aplicación, y un largo etcétera de funcionalidades más.

Pero antes de usarla, hemos de indicárselo a nuestro proyecto.

#### Añadir dependencias del proyecto

Si buscas “picasso android” en Google podrás acceder a [**su página en GitHub**](https://github.com/square/picasso), donde se detallan las instrucciones para usar Picasso en nuestros proyectos.

Lo primero es añadir la dependencia de dicha librería en nuestro proyecto, ya sea por **Gradle** o por **Maven**. La de Gradle indica la siguiente línea:

```
implementation 'com.squareup.picasso:picasso:2.8'
```

Para usar esa dependencia, hay que hacer click derecho sobre la carpeta de nuestro aplicación (app) y abrimos la opción **Open Module Settings**. En esa ventana, vamos a la sección de dependencias:

![ud06_pmdm_10.png](/img/user/adjuntos/2DAM_PMDM/Unidad_06/ud06_pmdm_10.png)

En la parte central se puede apreciar la lista de dependencias declaradas. En ella vamos a añadir la nuestra pulsando en el + y seleccionamos **Library Dependency**:

![ud06_pmdm_11.png](/img/user/adjuntos/2DAM_PMDM/Unidad_06/ud06_pmdm_11.png)

Esto abrirá una ventana para buscar dicha dependencia en el repositorio. En dicha ventana indicamos la ruta de la librería sin la versión. Es decir:

```
com.squareup.picasso:picasso
```

Y buscamos. El resultado se mostrará en la tabla inferior:

![ud06_pmdm_12.png](/img/user/adjuntos/2DAM_PMDM/Unidad_06/ud06_pmdm_12.png)

Seleccionamos la librería y la versión que queremos usar (que está en en la tabla de versiones de la derecha).

El segundo paso (Step 2) debe indicar que la configuración a la que añadimos esta dependencia es **implementation**, tal y como se indicaba más arriba.

Veremos en pocos segundos cómo Android Studio comienza a sincronizarse para descargar y añadir esa dependencia.

#### Ejemplos de uso

También permite aplicar **transformaciones** a las imágenes (redimensionar, recortar, redondear bordes, etc) o mostrar ***placeholders*** (imágenes de carga o error mientras se descarga la imagen principal).

Veamos un ejemplo:

```kotlin
val imageView = findViewById<ImageView>(R.id.imageView)
val picasso = Picasso.Builder(this).build()
picasso
    .load("https://i.imgur.com/DvpvklR.png")
    .resize(150, 150)
    .centerCrop()
    .into(imageView);
```

Desde su versión 3, Picasso una un `Builder` para instanciar los objetos. En nuestro caso, el objeto `picasso`, donde:

* **`load`** carga la imagen desde la URL especificada
* **`resize`**  redimensiona la imagen (en este caso a `500x500` píxeles)
* **`centerCrop`** recorta la imagen para que se ajuste al tamaño especificado **manteniendo el aspecto original**
* **`into(imageView)`** carga la imagen en el `ImageView` con id **`imageView`** creado en el [[2DAM_PMDM/Unidad 06/4. Palette Widgets#^ddd339\|apartado anterior]].

> [!info] 
> Como con cualquier otra librería, es necesario **importar** la de Picasso en nuestro código.
> Si no lo hacemos, el IDE nos lo recordará.

Si queremos asignar una "imagen previa" de precarga, un *placeholder*, a un `ImageView`, usamos el método `placeholder` indicándole la imagen:

```kotlin
picasso
    .load("https://example.com/imagen.jpg")
    .placeholder(R.drawable.ic_loading)
    .error(R.drawable.ic_error)
    .into(imageView)
```

Y para aplicar transformaciones[^1], como el redondeo de las esquinas, el método `transform`:  

```kotlin
picasso
    .load("https://example.com/imagen.jpg")
    .transform(RoundedCornersTransformation(10, 0))
    .into(imageView)
```

> [!warning] Cuidado
> Como los recursos son limitados en un dispositivo móvil, además de la velocidad de carga, se recomienda usar Picasso cuando la aplicación maneje una cantidad considerable de imágenes.
> 
> Es importante recordar que el uso de imágenes de la web implica un mayor consumo de datos para el usuario, sin contar con que la carga de imágenes puede ralentizarse si la conexión no es buena. Y si además se borra alguna de esas imágenes de la web, nuestra app mostraría un hueco que dejaría un gran vacío en el corazón (y la vista) de nuestros usuarios 🥺

> [!info] Consejo
> En general, las imágenes locales (guardadas en nuestro proyecto o dispositivo) suelen ser las que se usan como parte del diseño de la app.


## 4.2. ShapeableImageView

Es una extensión del estándar [[2DAM_PMDM/Unidad 06/4. Palette Widgets#^ec8ddb\|ImageView]] que permite crear formas personalizadas para imágenes.

Generalmente suele estar incluida en la paleta de widgets, ya que está incluida en las dependencias de la librería **material** de Google. Podemos comprobarlo en el fichero gradle del módulo de nuestra app o en la pantalla de dependencias que vimos anteriormente:

![ud06_pmdm_13.png](/img/user/adjuntos/2DAM_PMDM/Unidad_06/ud06_pmdm_13.png)

Como se puede ver en la figura anterior, la librería **material** está instalada en la versión `1.10.0`. Si no está incluida, solo hay que agregar la dependencia como ya hemos explicado anteriormente:

```
implementation 'com.google.android.material:material:1.6.0'
```

Para insertar esta view en nuestros layouts:

```xml
<com.google.android.material.imageview.ShapeableImageView
    android:id="@+id/shapeableImageView"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:src="@drawable/mi_imagen"
    android:padding="3dp"
    app:shapeAppearanceOverlay="@style/sivCircular"
    app:strokeColor="@color/my_stroke_color"
    app:strokeWidth="2dp" />
```

Donde:

* **`android:src`**: asigna la imagen a mostrar.

* **`app:shapeAppearanceOverlay`**: para aplicar una forma usando un estilo definido en alguno de los archivos de recursos.

* **`app:strokeColor`** y **`app:strokeWidth`** establecen el color y ancho de la línea de contorno de la imagen.

El estilo `sivCircular` y otros más se pueden incluir en un fichero nuevo, como puede ser el **`style_image.xml`** en **`res/value`**:

```xml
<resources>
    <style name="sivCircular">
        <item name="cornerSize">50%</item>
    </style>
    <style name="sivEsquinaRedondeada10">
        <item name="cornerSize">10%</item>
    </style>
    <style name="sivEsquinaRedondeada20">
        <item name="cornerSize">20%</item>
    </style>
    <style name="sivRedondeoRaro">
        <item name="cornerFamilyTopRight">rounded</item>
        <item name="cornerFamilyBottonLeft">rounded</item>
        <item name="cornerSizeTopRight">80dp</item>
        <item name="cornerSizeBottonLeft">80dp</item>
    </style>
    <style name="sivEsquinaCortada20">
        <item name="cornerFamily">cut</item>
        <item name="cornerSize">20dp</item>
    </style>
    <style name="sivDiamante">
        <item name="cornerFamily">cut</item>
        <item name="cornerSize">80dp</item>
    </style>
    <style name="sivCasita">
        <item name="cornerFamilyTopRight">cut</item>
        <item name="cornerFamilyTopLeft">cut</item>
        <item name="cornerSizeTopRight">80dp</item>
        <item name="cornerSizeTopLeft">80dp</item>
    </style>
    ...
</resources>
```

Donde cornerSize define el radio de las esquinas.

En el ejemplo anterior, el estilo **`sivDiamante20`** genera un efecto diamante la imagen si el `cornerSize` supera la mitad de la imagen.

> [!info] Info
> En el ejemplo anterior, al aplicar la forma circular en la imagen, el fondo del rectángulo contenedor aparece oscuro. Realmente se aplica transparencia para garantizar que la forma se muestra correctamente.

## 4.3. WebView

Este widget es un pequeño **navegador web** para mostrar contenido web en la app sin necesidad de que el usuario vaya a un navegador externo.

Imagina una aplicación de noticias. En lugar de abrir el navegador cada vez que quieres leer un artículo, la app puede mostrar el contenido dentro de un `WebView`. Esto ofrece una experiencia más fluida y personalizada para el usuario.

Para agregar un `WebView` a nuestro layout:  

```xml
<WebView
    android:id="@+id/webView"
    android:layout_width="match_parent"
    android:layout_height="match_parent" />
```

Para indicarle que cargue una web, se hace mediante código:  

```kotlin
val webView = findViewById<WebView>(R.id.webView)
webView.loadUrl("https://www.google.com")
```

En estos casos suele aparecer en la app la situación en la que se pide al usuario si quiere seguir usando el WebView de la app o si quiere abrir la página en un navegador externo. Para que se mantenga en la WebView es importante añadir lo siguiente:  

```kotlin
val webView = findViewById<WebView>(R.id.webView)
//Recoger el conjunto de settings del WebView
var webSettings: WebSettings = webView.getSettings()

//Habilitar el JavaScript en él
webSettings.javaScriptEnabled = true

/*
Indicar al WebView que el cliente por defecto será un WebView
y no directamente la app del navegador:
*/
webView.setWebViewClient(WebViewClient())

//Cargar la URL deseada:
webView.loadUrl("https://www.google.com")
```

En este código recuperamos los settings del webView **para habilitar el JavaScript** (que generalmente está deshabilitado) y establecer como cliente web el propio `WebView`. Todo ello antes de cargar la página web.

## 4.4. VideoView

Al igual que una `ImageView`, el `VideoView` permite cargar videos tanto en local (en tu proyecto o dispositivo móvil) como desde la web.

> [!warning] Recuerda...
> Como se ha indicado anteriormente, los recursos y el espacio son muy limitados en un dispositivo móvil, por lo que se recomienda la carga de dispositivos desde web.

En el layout:

```xml
<VideoView
    android:id="@+id/vvVideo"
    android:layout_width="match_parent"
    android:layout_height="match_parent" />
```

Para asignar una URL a nuestro `VideoView` no basta con indicarle la ruta. Es necesario realizar algunos pasos previos:

```kotlin
val vvVideo = findViewById<VideoView>(R.id.vvVideo)
val mcVideoWeb = MediaController(this)

mcVideoWeb.setAnchorView(vvVideo)
vvVideo.setVideoPath("https://file-examples.com/wp-content/storage/2017/04/file_example_MP4_480_1_5MG.mp4")

vvVideo.setMediaController(mcVideoWeb)
```

Se ha de crear un **MediaController** para **mostrar los controles de reproducción** de forma automática. Dicho MediaController se asocia al VideoView (setAnchorView), a éste se le indica la URL del vídeo y, por último, se le vincula el MediaController.

En caso de que el vídeo esté en un fichero local, lo guardaríamos en la carpeta correspondiente de los recursos. Por ejemplo, **res/raw/videoLocal.mp4**. Para acceder a dicho recurso desde código:

```kotlin
val vvVideoLocal = findViewById<VideoView>(R.id.vvVideoLocal)
val mcVideoLocal = MediaController(this)

mcVideoLocal.setAnchorView(vvVideoLocal)
val rutaVideo = "android.resource://"
                + packageName + "/"
                + R.raw.videoLocal)
vvVideoLocal.setVideoURI(Uri.parse(rutaVideo))
vvVideoLocal.setMediaController(mcVideoLocal)
vvVideoLocal.start()
```

Se establece la ruta del vídeo en el proyecto y se parsea dicha ruta para que sea una URI[^2] válida.

Se ha añadido una última línea para que el vídeo comience automáticamente. Se pueden ejecutar otros como pausar, detener, avanzar/retroceder, etc.

> [!info] 
> No todos los formatos de video son compatibles de forma nativa. Los aceptados y más habituales son **MP4** o [**3GP**](https://www.online-convert.com/es/formato-de-archivo/3gp). Para otros formatos menos habituales es posible que haya que hacer uso de librerías externas.

Es importante recalcar que no es buena idea usar vídeos locales ya que influyen en el rendimiento de la aplicación. La reproducción de vídeo puede consumir muchos recursos del dispositivo. Es importante optimizar el uso de la memoria y la batería.

> [!info] 
> Para reproducir videos desde un sitio web, recuerda dar [[2DAM_PMDM/Unidad 06/4. Palette Widgets#^85c065\|permisos para que tu aplicación pueda acceder a Internet]].

Se pueden implementar acciones a ejecutar cuando el vídeo finalice su reproducción. Para ello hay que suscribirse al evento `onCompletion`:

```kotlin
val vvVideoLocal = findViewById<VideoView>(R.id.vvVideoLocal)
val mcVideoLocal = MediaController(this)

mcVideoLocal.setAnchorView(vvVideoLocal)
val rutaVideo = "android.resource://"
                + packageName + "/"
                + R.raw.videoLocal)
vvVideoLocal.setVideoURI(Uri.parse(rutaVideo))
vvVideoLocal.setMediaController(mcVideoLocal)

videoView.setOnCompletionListener {
    // Acción a realizar cuando el video termina
    Toast.makeText(this,
                   "Video terminado",
                   Toast.LENGTH_SHORT).show()
}

vvVideoLocal.start()
```

## 4.5. CalendarView

Es un componente visual que permite mostrar un calendario interactivo dentro de la aplicación. Es como un mini calendario que se puede personalizar para mostrar diferentes vistas (día, semana, mes) y permitir al usuario seleccionar fechas.

![ud06_pmdm_14.png](/img/user/adjuntos/2DAM_PMDM/Unidad_06/ud06_pmdm_14.png)

En el layout, vamos a usar un `CalendarView` y un `TextView` en el que se escribirá la fecha seleccionada:

```xml
<CalendarView
    android:id="@+id/cvCalendario"
    android:layout_width="match_parent"
    android:layout_height="wrap_content" />

<TextView
    android:id="@+id/tvFecha"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:layout_marginTon="10dp"
    android:text="Fecha: " />
```

El `CalendarView` admite atributos como:

* **`android:firstDayOfWeek`**: establece el primer día de la semana (domingo o lunes).

* **`android:shownWeekNumber`**: muestra o oculta los números de semana.

* **`android:selectedDate`**: establece la fecha seleccionada por defecto.

También se le puede asociar una función al evento que recoja la pulsación en el calendario:

* **`OnDateChangeListener`**: permite detectar cuando el usuario selecciona una nueva fecha.

Veamos cómo mostrar la fecha seleccionada en el `TextView`:

```kotlin
val cvCalendario = findViewById<CalendarView>(R.id.cvCalendario)
val tvFecha = findViewById<TextView>(R.id.tvFecha)

calendarView.setOnDateChangeListener { view,
                                       year,
                                       month,
                                       dayOfMonth ->
    val fecha = "$dayOfMonth/${month + 1}/$year"
    tvFecha.text = "Fecha: $fecha"
    // Acción a realizar cuando se selecciona una fecha
    Toast.makeText(this,
                "Fecha seleccionada: $year-${month+1}-$dayOfMonth",
                Toast.LENGTH_SHORT).show()
}
```

Si queremos que el `CalendarView` muestre una fecha preseleccionada:

```kotlin
// Creamos un objeto Calendar con una fecha concreta
val calendario = Calendar.getInstance()
calendario.set(2025, 9, 21)

/Asignamos dicha fecha en milisegundos al CalendarView
cvCalendario.date = calendario.timeInMillis
```

Algunos atributos como el primer día de la semana también se puede establecer por código. Por ejemplo, si el primer día es el domingo, podemos cambiarlo a lunes de la siguiente forma:

```kotlin
// Creamos un objeto Calendar con una fecha concreta
val primerDiaSemana = cvCalendario.firstDayOfWeek
cvCalendario.firstDayOfWeek = (primerDiaSemana + 1) % 7
```

El **`% 7`** es importante en este ejemplo, ya que las semanas en sí son modulares.

## 4.7. SeekBar

Imagina el control físico de volumen de una mesa de mezclas o el regulador de intensidad (_dimmer_) de una bombilla en el salón. No eliges solo "encendido" o "apagado", sino el nivel exacto de intensidad deslizando un mando. Eso es, en esencia, una `SeekBar`.

Una `SeekBar` es una extensión del control `ProgressBar` que añade un pulgar deslizable (_thumb_). Permite al usuario seleccionar un valor continuo (o discreto) dentro de un rango prefijado moviendo dicho pulgar a la izquierda o derecha.

![ud06_pmdm_15.png](/img/user/adjuntos/2DAM_PMDM/Unidad_06/ud06_pmdm_15.png)

> Fuente: *Discrete seekbar in android*. (2022, julio 12). GeeksforGeeks. https://www.geeksforgeeks.org/android/discrete-seekbar-in-android/

Probemos a incluir una en nuestro layout `activity_main.xml`:

```xml
<LinearLayout 
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:orientation="vertical"
    android:padding="16dp">

    <TextView
        android:id="@+id/tvVolumeLevel"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Nivel de volumen: 0"
        android:textSize="18sp" />

    <SeekBar
        android:id="@+id/seekBarVolume"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:max="100"
        android:progress="0"
        android:layout_marginTop="8dp" />
</LinearLayout>
```

Para gestionar la `SeekBar`, implementamos la interfaz `SeekBar.OnSeekBarChangeListener`. Aplicando Clean Code, encapsulamos la lógica de configuración en un método específico.

```kotlin
package com.example.pmdm.ui

import android.os.Bundle
import android.widget.SeekBar
import android.widget.TextView
import androidx.appcompat.app.AppCompatActivity
import com.example.pmdm.R

/**
 * Pantalla principal que demuestra la gestión de eventos con SeekBar.
 *
 * @author Profesor PMDM
 */
class MainActivity : AppCompatActivity() {

    private lateinit var tvVolumeLevel: TextView
    private lateinit var seekBarVolume: SeekBar
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)
        
        initViews()
        setupSeekBar()
    }
    
    /**
     * Inicializa las referencias a los componentes de la vista.
     */
    private fun initViews() {
        tvVolumeLevel = findViewById(R.id.tvVolumeLevel)
        seekBarVolume = findViewById(R.id.seekBarVolume)
    }
    
    /**
     * Configura el listener para capturar los cambios en la SeekBar.
     */
    private fun setupSeekBar() {
        seekBarVolume.setOnSeekBarChangeListener(object : SeekBar.OnSeekBarChangeListener {
            
            override fun onProgressChanged(seekBar: SeekBar?,
                        progress: Int,
                        fromUser: Boolean) {
                        
                // Se invoca cuando cambia la posición de la barra
                if (fromUser) {
                    updateVolumeLabel(progress)
                }
            }
            
            override fun onStartTrackingTouch(seekBar: SeekBar?) {
                // Opcional: Feedback visual o sonoro al pulsar el mando
            }
            
            override fun onStopTrackingTouch(seekBar: SeekBar?) {
                // Opcional: Guardar preferencia o ejecutar acción final al soltar
            }
        })
    }
    
    /**
     * Actualiza el texto con el valor actual del volumen.
     *
     * @param volume Nivel de volumen entre 0 y 100.
     */
    private fun updateVolumeLabel(volume: Int) {
        tvVolumeLevel.text = getString(R.string.volume_level_format, volume)
    }
}
```

> [!warning] Buenas Prácticas
> Asegúrate de incluir en tu `strings.xml`:
> ```xml
> <string name="volume_level_format">Nivel de volumen: %1$d</string>
> ```
> 
> ¡Evita la concatenación directa de cadenas dentro del código!

Es importante no olvida el parámetro `max`. Si no se define `android:max` en el XML, el **valor por defecto es 100**, pero si necesitamos otro rango (ej. 0 a 10) debemos configurarlo explícitamente.

> [!info] 
> El valor mínimo por defecto siempre es 0 en vistas estándar.

## 4.8. RatingBar

¿Conoces la ficha de un producto en Amazon o el sistema de valoración de una app en Google Play Store? En lugar de pedir al usuario que introduzca un entero del 1 al 5 en un campo de texto, le presentan 5 estrellas donde puede marcar directamente la puntuación deseada (incluso valores medios como 3.5 estrellas).

Una `RatingBar` es una extensión directa de `AbsSeekBar` (y por tanto, emparentada con la `SeekBar`) que muestra una valoración mediante estrellas o iconos repetitivos. Permite al usuario seleccionar un grado de satisfacción o puntuación de forma visual e intuitiva.

Veámoslo en nuestro layout:

```xml
<LinearLayout 
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:orientation="vertical"
    android:padding="16dp">

    <TextView
        android:id="@+id/tvRatingScore"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Puntuación: 0.0 / 5.0"
        android:textSize="18sp" />

    <RatingBar
        android:id="@+id/ratingBarProduct"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:numStars="5"
        android:rating="2.5"
        android:stepSize="0.5"
        android:isIndicator="false"
        android:layout_marginTop="8dp" />
</LinearLayout>
```

Para responder a los cambios en la puntuación, asignamos la interfaz `RatingBar.OnRatingBarChangeListener`:

```kotlin
package com.example.pmdm.ui

import android.os.Bundle
import android.widget.RatingBar
import android.widget.TextView
import androidx.appcompat.app.AppCompatActivity
import com.example.pmdm.R

/**
 * Pantalla de evaluación que demuestra la captura de eventos con RatingBar.
 *
 * @author Profesor PMDM
 */
class RatingActivity : AppCompatActivity() {

    private lateinit var tvRatingScore: TextView
    private lateinit var ratingBarProduct: RatingBar

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_rating)

        initViews()
        setupRatingBar()
    }

    /**
     * Inicializa las referencias a los componentes de la vista.
     */
    private fun initViews() {
        tvRatingScore = findViewById(R.id.tvRatingScore)
        ratingBarProduct = findViewById(R.id.ratingBarProduct)
    }

    /**
     * Configura el listener para registrar la valoración seleccionada.
     */
    private fun setupRatingBar() {
        ratingBarProduct.onRatingBarChangeListener = 
            RatingBar.OnRatingBarChangeListener { _, rating, fromUser ->
                if (fromUser) {
                    updateRatingLabel(rating)
                }
            }
    }

    /**
     * Actualiza el TextView con el formato de la valoración actual.
     *
     * @param rating Valor numérico flotante asignado por el usuario.
     */
    private fun updateRatingLabel(rating: Float) {
        tvRatingScore.text = getString(R.string.rating_score_format, rating)
    }
}
```

> [!warning] Buenas Prácticas
> Recuerda usar `strings.xml` para los textos de la app. En este caso, incluiremos:
> ```xml
> <string name="rating_score_format">Puntuación: %1$.1f / 5.0</string>
> ```

> [!info] 
> Si queremos usar la `RatingBar` **únicamente para mostrar** una nota media (por ejemplo, en un listado de reseñas) y no para que el usuario la modifique, debemos establecer **`android:isIndicator="true"`** en el XML. De lo contrario, el usuario podrá interactuar con ella.

> [!info] Para ajustar la precisión...
> ...usar el parámetro `stepSize`, indicando el incremento mínimo (`0.5` para medias estrellas, `1.0` para valores enteros).
> Acepta tipos `Float`, por lo que la firma de los métodos **maneja siempre `Float`** y no `Int` o `Double`.

> [!warning] Cuidado
> No se debe confundir `numStars` con la puntuación máxima real. **`android:numStars`** define cuántas estrellas se muestran, pero si no se ajusta la escala correctamente, la barra podría tener 5 estrellas y permitir valores mayores si se altera el `max` de `AbsSeekBar` por código.

## 4.9. SearchView

Un `SearchView` es campo de texto con superpoderes: conforme vamos escribiendo letra a letra lo que queremos buscar, `SearchView` nos va mostrando las coincidencias que va encontrando. Tiene un botón de cancelación y búsqueda para permitir al usuario filtrar conjuntos de datos (como un `RecyclerView` o `ListView`) o para lanzar consultas.

Pongamos uno en nuestra pantalla:


```xml
<LinearLayout 
    xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    android:padding="16dp">

    <androidx.appcompat.widget.SearchView
        android:id="@+id/searchViewUsers"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        app:iconifiedByDefault="false"
        app:queryHint="Buscar usuario por nombre..." />

    <TextView
        android:id="@+id/tvSearchResult"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:layout_marginTop="16dp"
        android:text="Realiza una búsqueda..."
        android:textSize="16sp" />
</LinearLayout>
```

Como es de esperar, al escribir estamos realizando una acción que la app percibe como un evento. Por tanto, para responder a esos eventos de escritura o de envío en la búsqueda, implementamos la interfaz `SearchView.OnQueryTextListener`.

```kotlin
package com.example.pmdm.ui

import android.os.Bundle
import android.widget.TextView
import androidx.appcompat.app.AppCompatActivity
import androidx.appcompat.widget.SearchView
import com.example.pmdm.R

/**
 * Actividad que demuestra la captura de eventos en un SearchView.
 *
 * @author Profesor PMDM
 */
class SearchActivity : AppCompatActivity() {

    private lateinit var searchViewUsers: SearchView
    private lateinit var tvSearchResult: TextView

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_search)

        initViews()
        setupSearchView()
    }

    /**
     * Inicializa las referencias a los componentes visuales.
     */
    private fun initViews() {
        searchViewUsers = findViewById(R.id.searchViewUsers)
        tvSearchResult = findViewById(R.id.tvSearchResult)
    }

    /**
     * Configura el listener para capturar la entrada de texto en el SearchView.
     */
    private fun setupSearchView() {
        searchViewUsers.setOnQueryTextListener(object : SearchView.OnQueryTextListener {
            
            override fun onQueryTextSubmit(query: String?): Boolean {
                // Se invoca cuando el usuario pulsa el botón de 'Buscar' en el teclado
                query?.let {
                    processSearchSubmit(it)
                }
                // Retornamos true para indicar que hemos manejado el evento de envío
                return true
            }

            override fun onQueryTextChange(newText: String?): Boolean {
                // Se invoca en tiempo real cada vez que cambia el texto del campo
                val filterText = newText.orEmpty()
                filterResultsInRealTime(filterText)
                return true
            }
        })
    }

    /**
     * Procesa la búsqueda definitiva enviada por el usuario.
     *
     * @param query Término final introducido.
     */
    private fun processSearchSubmit(query: String) {
        tvSearchResult.text = getString(R.string.search_submitted_format, query)
        // Cierra el teclado virtual al enviar
        searchViewUsers.clearFocus()
    }

    /**
     * Aplica el filtro en tiempo real según el texto escrito.
     *
     * @param filterText Texto parcial introducido por el usuario.
     */
    private fun filterResultsInRealTime(filterText: String) {
        if (filterText.isEmpty()) {
            tvSearchResult.text = getString(R.string.search_empty_prompt)
        } else {
            tvSearchResult.text = getString(R.string.search_filtering_format, filterText)
        }
    }
}
```
