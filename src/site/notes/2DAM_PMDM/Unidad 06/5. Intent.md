Las aplicaciones móviles suelen navegar entre distintas pantallas (*activities*) pasando información de unas a otras.

El funcionamiento es similar a la forma en la que se hace en la web, donde de una página se toman datos en un formulario (`<form>`) que contiene el lugar al que va a enviar los datos que contiene (action), la forma de hacerlo (method) y finalmente los datos en sí.

Algo parecido ocurre con las *activities* de una aplicación Android. Y todo ello se hace usando el objeto [**Intent**](https://developer.android.com/guide/components/intents-filters?hl=es-419).

> [!info] 
> Un `Intent` permite el traspaso de datos entre distintas activities de nuestra app o entre una de nuestras activities y otra aplicación externa. Esto ocurre, por ejemplo, cuando desde una de pantalla se pulsa sobre un enlace y aparece una pantalla indicando con qué navegador queremos abrir dicho enlace.

El uso de [**Intents**](https://developer.android.com/guide/components/intents-filters?hl=es-419) sigue siendo el pilar de la navegación en Android, aunque existen alternativas como el componente de [**Navigation**](https://developer.android.com/guide/navigation?hl=es-419) de [**Jetpack**](https://developer.android.com/jetpack?hl=es-419).

Entender los `Intents` es esencial para comprende cómo comunicar las activities de nuestra app entre sí o con otras apps externas.

Un `Intent` (intención) es un objeto de mensajería que puede usarse para solicitar una acción de otro componente de la aplicación (o de otra app). El uso más común es **iniciar una Activity**.

Existen dos tipos de `Intent`:

* **💡 Intents explícitos:** definen exactamente qué componente (clase) se debe ejecutar. Se usan principalmente para **navegar entre las pantallas de nuestra propia aplicación**.

* **Intents implícitos:** no nombran un componente específico, sino que declaran una acción general a realizar (ej. abrir una página web, hacer una foto). El sistema Android busca qué apps instaladas pueden manejar esa "intención".

Vamos a centrarnos en los primeros: los `Intent` **explícitos**.

## 5.1. Intents explícitos

### 5.1.1. Ir de una activity a otra

Si queremos permitir que nuestra app vaya de una pantalla (activity) a otra, podemos programarlo en el código de la `Activity` de la siguiente forma:

```kotlin
...
btAceptar.setOnClickListener {
    val intent = Intent(this, UserDetailsActivity::class.java)
    startActivity(intent)
}
...
```

Lo primero es crear un objeto `Intent` al que le damos los siguientes datos en su constructor:

1. El contexto desde el que se lanza esta petición.  
   En el ejemplo es **`this`**, refiriéndose al objeto de la activity en la que estamos.

2. La `activity` a la que queremos dirigirnos desde aquí.  
   La forma de expresarla es:

   ```kotlin
   ActivityDestino::class.java
   ```

   Donde obtenemos una instancia de la clase en Java de la instancia en Kotlin de la misma clase. En otras palabras, le enviamos el objeto de la **activity destino**.

Después indicamos que queremos que se cargue la pantalla destino con la función `startActivity`, a la que le pasamos el `Intent`.

### 5.1.2. Enviar datos a la activity de destino

Si además de ir de una activity a otra queremos que se envíen datos a esa pantalla de destino, hemos de añadir esos datos al `Intent` con su método putExtra antes de ejecutar el envío con startActivity.

El envío de datos mediante el `Intent` se hace en un par clave-valor. La clave la ponemos nosotros (si es posible, con una nomenclatura específica o como si fuesen constantes). Así, podemos enviar por ejemplo el String del nombre de usuario de la siguiente forma:

```kotlin
intent.putExtra("USER_NAME", etUsuario.text.toString())
```

En el siguiente código mostramos un ejemplo de cómo asociar el envío de datos a un botón: 

```kotlin
class MainActivity : AppCompatActivity() {
   override fun onCreate(savedInstanceState: Bundle?) {
       super.onCreate(savedInstanceState)
       enableEdgeToEdge()
       setContentView(R.layout.activity_main)
       ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main)) { v, insets ->
           val systemBars = insets.getInsets(WindowInsetsCompat.Type.systemBars())
            v.setPadding(systemBars.left,
                        systemBars.top,
                        systemBars.right,
                        systemBars.bottom)
            insets
       }

       val etUsuario = findViewById<EditText>(R.id.etUsuario)
       val btAceptar = findViewById<Button>(R.id.btAceptar)

       btAceptar.setOnClickListener {
           if (etUsuario.text.isNotEmpty()) {
               val intent = Intent(this, UserDetailsActivity::class.java)
               intent.putExtra("USER_NAME", etUsuario.text.toString())
               startActivity(intent)
           }
           else {
               Toast.makeText(this,
                   "Debe indicar un nombre de usuario",
                   Toast.LENGTH_SHORT)
                   .show()
           }
       }
   }
}
```

En la actualidad, la forma recomendada de usar el [**Intent**](https://developer.android.com/guide/components/intents-filters?hl=es-419) es usando el método **`.apply()`**:

```kotlin
val intent = Intent(this, UserDetailsActivity::class.java).apply {
    putExtra("USER_NAME", etUsuario.text.toString())
}
startActivity(intent)
```

De esta forma se engloban los datos a enviar.

### 5.1.3. Recoger los datos enviados desde la activity

En la activity destino podemos recuperar los datos enviados desde la activity origen. Todas las activities tienen una propiedad **intent** que nos permiten recuperar cualquier información enviada a dicha activity.

⚠️ Es importante tener presente que se pueda llegar a una activity desde más de un origen y que no en todos se envíe la misma información, por lo que al recuperar los datos hay que tener claro que pueden ser nulos.

Para recuperar datos usamos los métodos “`get-`” de intent, como: 

```kotlin
class UserDetailsActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContentView(R.layout.activity_user_details)
        ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main))
            { v, insets ->
                val systemBars = insets
                   .getInsets(WindowInsetsCompat.Type.systemBars())
                v.setPadding(systemBars.left,
                        systemBars.top,
                        systemBars.right,
                        systemBars.bottom)
                insets
            }
		getUserName()
		
		val btVolver = findViewById<Button>(R.id.btVolver)
		btVolver.setOnClickListener {
			onBackPressed()
		}
    }
        
	fun getUserName() {
		val userName = intent.getStringExtra("USER_NAME")
					?: "Desconocido"
		val tvDetails = findViewById<TextView>(R.id.tvDetails)
		tvDetails.text = userName
	}
}
```

### 5.1.4. Paso de objetos complejos (Parcelable)

Aunque tradicionalmente se usaba la interfaz **Serializable** de Java, en Android es mucho más eficiente usar [**Parcelable**](https://developer.android.com/kotlin/parcelize?hl=es-419). Gracias a Kotlin podemos usar la anotación **@Parcelize** para evitar escribir todo el código repetitivo de la implementación manual.


> [!warning] Cuidado
> Hay que asegurarse de tener el plugin de Kotlin **`Parcelize`** en tu fichero `build.gradle` (nivel de módulo):
> ```
> plugins {
>     id 'kotlin-parcelize'
> }
> ```

Para definir un objeto parcelable:  

```kotlin
import android.os.Parcelable
import kotlinx.parcelize.Parcelize
@Parcelize
data class User(val name: String, val age: Int) : Parcelable
```

Y para enviar el objeto:  

```kotlin
val user = User("Beatriz", 22)
val intent = Intent(this, DetailActivity::class.java)
intent.putExtra("EXTRA_USER_OBJECT", user)
startActivity(intent)
```

Para recuperarlos desde la activity destinataria:

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    binding = ActivityDetailBinding.inflate(layoutInflater)
    setContentView(binding.root)

    // Recuperar tipos primitivos (se puede definir un valor por defecto)
    val name = intent.getStringExtra("EXTRA_USER_NAME") ?: "Desconocido"
    val age = intent.getIntExtra("EXTRA_USER_AGE", 0)

    // Recuperar objetos Parcelable (Versión moderna Android 13+)
    val user = if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {
        intent.getParcelableExtra("EXTRA_USER_OBJECT", User::class.java)
    } else {
        @Suppress("DEPRECATION")
        intent.getParcelableExtra<User>("EXTRA_USER_OBJECT")
    }

    binding.tvInfo.text = "Bienvenido $name, edad: $age"
}
```
