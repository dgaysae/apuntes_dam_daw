Desde Java 11, **JavaFX no viene incluido en el JDK**: es una biblioteca aparte (OpenJFX). La forma más cómoda de usarla es dejar que **Maven** la descargue y la configure por nosotros, igual que cualquier otra dependencia. Es lo que hacen los asistentes de NetBeans y de Visual Studio Code.

## 3.1. Crear el proyecto en NetBeans

1. **File → New Project…**
2. Categoría **Java with Maven** y tipo de proyecto **FXML JavaFX Maven Archetype (Gluon)**.
3. Escribe el nombre del proyecto (*Project Name*), el *Group Id* (por ejemplo, `es.dam`) y el paquete (*Package*).
4. **Finish**. La primera vez, Maven tardará un poco en descargar las bibliotecas de JavaFX.

Para ejecutarlo, usa **Run Project (F6)**. Aparecerá una ventana de ejemplo con un botón que cambia a una segunda vista.

> [!TIP] Usa un JDK reciente
> Las versiones actuales de JavaFX necesitan, como mínimo, **JDK 17**. Si el proyecto no compila, comprueba en las propiedades del proyecto (*Build → Compile*) qué JDK usa.

## 3.2. Qué archivos genera el asistente

```
MiAppFX/
├── pom.xml                        ← dependencias de JavaFX y plugin javafx-maven-plugin
└── src/main/
    ├── java/
    │   ├── module-info.java       ← declaración del módulo
    │   └── es/dam/miappfx/
    │       ├── App.java           ← clase principal (extiende Application)
    │       ├── PrimaryController.java
    │       └── SecondaryController.java
    └── resources/
        └── es/dam/miappfx/
            ├── primary.fxml       ← vistas
            └── secondary.fxml
```

- El código Java va en `src/main/java`, y las **vistas FXML, hojas de estilo e imágenes**, en `src/main/resources`, **dentro de una carpeta con la misma ruta que el paquete**. Así, la clase principal puede cargarlas por su nombre, sin ruta (ver [[Asignaturas/1DAM_Programación/Apuntes/Unidad 06/Anexo - JavaFX/Apéndice - recursos del proyecto\|Apéndice - recursos del proyecto]]).
- Puedes reutilizar las vistas y los controladores de ejemplo para tu aplicación, o borrarlos y crear los tuyos.

### El archivo `module-info.java`

JavaFX está organizado en **módulos** (`javafx.controls`, `javafx.fxml`…), y el asistente convierte también tu proyecto en un módulo. Su archivo `module-info.java` es algo así:

```java
module es.dam.miappfx {
    requires javafx.controls;
    requires javafx.fxml;

    opens es.dam.miappfx to javafx.fxml;
    exports es.dam.miappfx;
}
```

- `requires` indica los módulos de JavaFX que usa la aplicación.
- `opens … to javafx.fxml` permite que el cargador de FXML acceda a los atributos y métodos **privados** de los controladores (los que llevan `@FXML`).
- `exports` hace visible el paquete para que JavaFX pueda crear la clase principal.

> [!WARNING] Error típico: `LoadException` al cargar el FXML
> Si mueves los controladores a **otro paquete** (por ejemplo, `es.dam.miappfx.controladores`), tienes que añadir también para él una línea `opens es.dam.miappfx.controladores to javafx.fxml;`. Si no, el programa compila, pero falla al cargar la vista.

## 3.3. Crear el proyecto en Visual Studio Code

Con las extensiones de Java de Microsoft (*Extension Pack for Java*, que incluye Maven), Visual Studio Code también tiene un asistente para JavaFX:

1. En el explorador de archivos, pulsa **Create Java Project**.  
   ![ud06_javafx_vscode_01.png](/img/user/adjuntos/1DAM_Programacion/Unidad_06/ud06_javafx_vscode_01.png)
2. Elige el tipo de proyecto **JavaFX**.  
   ![ud06_javafx_vscode_02.png](/img/user/adjuntos/1DAM_Programacion/Unidad_06/ud06_javafx_vscode_02.png)
3. Responde a las preguntas: *group id* (el paquete), *artifact id* (el nombre del proyecto) y versión (`1.0-SNAPSHOT`, es decir, «versión en desarrollo»).

Se genera un proyecto Maven con la misma estructura que el de NetBeans. Para ejecutarlo, abre la vista **Maven** y lanza el objetivo `javafx:run`.

## 3.4. Desde la línea de comandos (sin IDE)

Si el proyecto es de Maven, basta con ejecutar en su carpeta:

```bash
mvn javafx:run
```

Sin Maven, hay que descargar el **JavaFX SDK** de [gluonhq.com/products/javafx](https://gluonhq.com/products/javafx/), descomprimirlo e indicar dónde están sus bibliotecas (`--module-path`) y qué módulos se usan (`--add-modules`) **tanto al compilar como al ejecutar**:

```bash
javac --module-path /ruta/javafx-sdk-21/lib \
      --add-modules javafx.controls,javafx.fxml \
      -d out src/es/dam/TuApp.java

java --module-path /ruta/javafx-sdk-21/lib \
     --add-modules javafx.controls,javafx.fxml \
     -cp out es.dam.TuApp
```

La barra invertida (`\`) al final de línea indica que el comando continúa en la línea siguiente (en Linux y macOS). En Windows, escribe cada comando en una sola línea, con la ruta del SDK al estilo de Windows (`C:\javafx-sdk-21\lib`).

> [!NOTE]
> La variable `CLASSPATH` no sirve para JavaFX 11 o superior: sus bibliotecas son módulos y hay que pasarlas con `--module-path`. Por eso es mucho más cómodo trabajar con Maven.
