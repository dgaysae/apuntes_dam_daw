La mejor forma de comprender las piezas de una aplicación JavaFX ([[Asignaturas/1DAM_Programación/Apuntes/Unidad 06/Anexo - JavaFX/2. Qué es JavaFX#2.2. Las piezas de una aplicación JavaFX\|2.2]]) es verlas funcionando juntas. Vamos a construir una aplicación que pide un número al usuario y muestra su **tabla de multiplicar**:

![ud06_javafx_fxml_01.png](/img/user/adjuntos/1DAM_Programacion/Unidad_06/ud06_javafx_fxml_01.png)

Parte de un proyecto creado con el asistente de NetBeans ([[Asignaturas/1DAM_Programación/Apuntes/Unidad 06/Anexo - JavaFX/3. Crear un proyecto JavaFX\|3. Crear un proyecto JavaFX]]) con el paquete `es.dam.tabla`. Estos son los archivos que vamos a escribir:

```
src/main/java/es/dam/tabla/TablaApp.java          ← clase principal
src/main/java/es/dam/tabla/TablaController.java   ← controlador
src/main/java/es/dam/tabla/TablaMultiplicar.java  ← modelo
src/main/resources/es/dam/tabla/tabla.fxml        ← vista
```

## 4.1. La clase principal

La clase principal carga la vista FXML, la coloca en una escena y muestra la ventana:

```java
package es.dam.tabla;

import java.io.IOException;
import javafx.application.Application;
import javafx.fxml.FXMLLoader;
import javafx.scene.Parent;
import javafx.scene.Scene;
import javafx.stage.Stage;

public class TablaApp extends Application {

    @Override
    public void start(Stage ventana) throws IOException {
        Parent raiz = FXMLLoader.load(getClass().getResource("tabla.fxml"));
        ventana.setTitle("Tabla de multiplicar");
        ventana.setScene(new Scene(raiz, 400, 300));
        ventana.show();
    }

    public static void main(String[] args) {
        launch(args);
    }
}
```

- **`main()`** solo llama a **`launch(args)`**, un método heredado de `Application` que pone en marcha JavaFX.
- Cuando JavaFX está listo, llama a **`start(Stage ventana)`**, el verdadero punto de entrada de la aplicación. El parámetro es la **ventana principal**, que crea JavaFX.
- **`FXMLLoader.load()`** lee el archivo FXML y construye con él el árbol de nodos. Como `tabla.fxml` está en `resources`, en la misma ruta que el paquete de la clase, basta con su nombre. Puede lanzar `IOException` si no encuentra el archivo; por eso `start()` la declara con `throws`.
- `setTitle()` pone el título de la ventana, `setScene()` le asigna una escena de 400 × 300 píxeles con ese árbol y **`show()`** la muestra. Sin `show()`, no aparece nada.

## 4.2. La vista (FXML)

El archivo FXML describe qué nodos tiene la interfaz y cómo se organizan. Léelo con calma; después lo comentamos.

```xml
<?xml version="1.0" encoding="UTF-8"?>

<?import javafx.scene.control.Button?>
<?import javafx.scene.control.Label?>
<?import javafx.scene.control.TextField?>
<?import javafx.scene.layout.VBox?>

<VBox alignment="CENTER" spacing="20.0"
      xmlns="http://javafx.com/javafx/21"
      xmlns:fx="http://javafx.com/fxml/1"
      fx:controller="es.dam.tabla.TablaController">
   <children>
      <Label text="Tabla de multiplicar" />
      <TextField fx:id="campoNumero" promptText="Escribe un número" />
      <Button text="Calcular tabla" onAction="#mostrarTabla" />
      <Label fx:id="etiquetaResultado" />
   </children>
</VBox>
```

- La primera línea indica la versión de XML y la codificación.
- Las instrucciones **`<?import …?>`** equivalen a los `import` de Java: indican las clases de los nodos que se usan.
- El elemento raíz es un **`VBox`**, un **contenedor** que coloca sus hijos en una columna ([[Asignaturas/1DAM_Programación/Apuntes/Unidad 06/Anexo - JavaFX/5. Contenedores (layouts)\|5. Contenedores (layouts)]]). Sus atributos fijan la alineación (`CENTER`) y la separación entre hijos (20 píxeles).
- **`xmlns`** y **`xmlns:fx`** declaran los espacios de nombres de JavaFX. El segundo es **obligatorio** si se usan atributos con el prefijo `fx:`, como `fx:id` o `fx:controller`.
- **`fx:controller`** indica la clase controladora, **con su paquete**.
- Dentro de `<children>` están los nodos hijos: dos etiquetas (`Label`), un campo de texto (`TextField`) y un botón (`Button`).
- **`fx:id`** da un nombre a un nodo para poder usarlo desde el controlador. Solo lo necesitan los nodos que el controlador consulta o modifica.
- **`onAction="#mostrarTabla"`** indica qué método del controlador se ejecuta al pulsar el botón.

> [!TIP] FXML o código Java
> La misma interfaz se puede construir desde Java, creando el contenedor y añadiéndole los nodos uno a uno (`vbox.getChildren().add(…)`). Es más largo y mezcla diseño y lógica, pero es la opción adecuada cuando los nodos se crean **mientras se ejecuta el programa**: por ejemplo, un botón por cada producto de una lista, creados con un bucle.

## 4.3. El controlador

El controlador **responde a los eventos** de la vista y **modifica sus nodos**:

```java
package es.dam.tabla;

import javafx.fxml.FXML;
import javafx.scene.control.Label;
import javafx.scene.control.TextField;

public class TablaController {

    @FXML
    private TextField campoNumero;

    @FXML
    private Label etiquetaResultado;

    private final TablaMultiplicar modelo = new TablaMultiplicar();

    @FXML
    private void initialize() {
        etiquetaResultado.setText("Escribe un número y pulsa el botón");
    }

    @FXML
    private void mostrarTabla() {
        try {
            int n = Integer.parseInt(campoNumero.getText().trim());
            etiquetaResultado.setText(modelo.generar(n));
        } catch (NumberFormatException e) {
            etiquetaResultado.setText("Eso no es un número entero");
        }
    }
}
```

- Los atributos **`campoNumero`** y **`etiquetaResultado`** se llaman **igual** que los `fx:id` del FXML y son del **mismo tipo**. Al cargar la vista, `FXMLLoader` crea los nodos y los asigna a estos atributos, así que el controlador puede usarlos.
- **`@FXML`** marca los atributos y métodos que `FXMLLoader` tiene que enlazar con el FXML. Hace falta porque son **privados**; si fueran públicos, no sería necesaria, pero es buena práctica ponerla siempre y mantenerlos privados.
- **`mostrarTabla()`** es el método indicado en `onAction`: se ejecuta cada vez que se pulsa el botón. Lee el texto del campo con **`getText()`**, pide la tabla al modelo y la muestra en la etiqueta con **`setText()`**.
- Si el usuario no escribe un número, `parseInt()` lanza **`NumberFormatException`**. La capturamos para mostrar un aviso en lugar de que falle la aplicación.
- **`initialize()`**, si existe, se ejecuta **automáticamente** al terminar de cargar la vista, cuando los atributos `@FXML` ya tienen sus nodos. Sirve para preparar la interfaz: textos iniciales, valores por defecto, cargar una imagen… Es opcional.

> [!WARNING] No inicialices los nodos en el constructor
> Cuando se ejecuta el constructor del controlador, `FXMLLoader` todavía no ha asignado los nodos y los atributos `@FXML` valen `null`. Usa `initialize()`.

## 4.4. El modelo

El cálculo de la tabla no tiene nada que ver con la interfaz, así que lo sacamos a una clase aparte, el **modelo**:

```java
package es.dam.tabla;

public class TablaMultiplicar {

    public String generar(int n) {
        StringBuilder tabla = new StringBuilder();
        for (int i = 1; i <= 10; i++) {
            tabla.append(n).append(" x ").append(i)
                 .append(" = ").append(n * i).append("\n");
        }
        return tabla.toString();
    }
}
```

En un ejemplo tan pequeño podría ir dentro del controlador, pero separarlo tiene ventajas: el modelo se puede **probar** sin interfaz y **reutilizar** en otra aplicación (de consola, web…). En aplicaciones reales, el modelo es el que lee y guarda ficheros, accede a bases de datos o hace los cálculos.

## 4.5. Cómo encaja todo

Esto es lo que ocurre desde que se ejecuta la aplicación hasta que se ve la tabla:

1. `main()` llama a `launch()`, y JavaFX llama a `start()` con la ventana principal.
2. `FXMLLoader` lee `tabla.fxml`: crea los nodos, crea un objeto `TablaController`, le asigna los nodos con `fx:id` y llama a su `initialize()`.
3. `start()` pone el árbol de nodos en una escena y muestra la ventana.
4. El programa **espera**. Cuando el usuario pulsa el botón, se produce un **evento** (`ActionEvent`) y JavaFX llama al método asociado, `mostrarTabla()`.
5. `mostrarTabla()` lee el campo de texto, pide la tabla al modelo y actualiza la etiqueta.

El paso 4 es la clave de las interfaces gráficas: el programa no sigue un orden fijo, sino que **reacciona a los eventos** del usuario. Es la **programación dirigida por eventos**, que verás en [[Asignaturas/1DAM_Programación/Apuntes/Unidad 06/Anexo - JavaFX/7. Eventos y manejadores\|7. Eventos y manejadores]].
