## 7.1. Programación dirigida por eventos

En un programa de consola, las instrucciones se ejecutan en un orden fijo: pedir un dato, calcular, mostrar. En una interfaz gráfica, el programa muestra la ventana y **espera**. Es el usuario quien decide qué ocurre: pulsar un botón, escribir en un campo, mover el ratón, cerrar la ventana…

Cada una de esas acciones produce un **evento**: un objeto que describe lo que ha pasado (qué tipo de acción, sobre qué nodo, en qué posición…). Para que el programa reaccione, asociamos al nodo un **manejador de eventos** (*event handler*, también llamado *listener*): un método que JavaFX ejecuta cuando se produce ese evento.

Esta forma de programar se llama **programación dirigida por eventos**.

## 7.2. Tipos de eventos

| Evento | Cuándo se produce | Manejador del nodo |
|---|---|---|
| **`ActionEvent`** | La acción principal de un control: pulsar un botón, elegir una opción de menú, pulsar Intro en un `TextField`, elegir un valor en un `ComboBox`… | `onAction` |
| **`MouseEvent`** | Clic, doble clic, entrar o salir del nodo, mover o arrastrar el ratón. | `onMouseClicked`, `onMouseEntered`, `onMouseExited`, `onMouseMoved`… |
| **`KeyEvent`** | Pulsar o soltar una tecla, o escribir un carácter, con el foco en el nodo. | `onKeyPressed`, `onKeyReleased`, `onKeyTyped` |
| **`ScrollEvent`** | Mover la rueda del ratón o desplazar en un panel táctil. | `onScroll` |
| **`DragEvent`** | Arrastrar y soltar elementos sobre el nodo. | `onDragOver`, `onDragDropped`… |
| **`WindowEvent`** | Mostrar, ocultar o cerrar la ventana (se asocia al `Stage`). | `onCloseRequest`, `onShown`… |

Con `ActionEvent` no hace falta saber cómo se ha activado el control (con el ratón, con el teclado…): basta con saber que se ha activado. Por eso es el evento que más usarás.

## 7.3. Manejadores desde FXML

Es la forma más habitual. En el FXML, el atributo del evento indica el método del controlador, precedido de `#`:

```xml
<Button text="Haz clic" onAction="#pulsarBoton" />
<Label fx:id="zona" text="Haz doble clic aquí" onMouseClicked="#clicEnZona" />
<TextField fx:id="campo" onKeyPressed="#teclaPulsada" />
```

En el **controlador** se escribe el método con ese nombre. Puede no tener parámetros o recibir el **objeto del evento**, si necesita información sobre él:

```java
public class EjemploController {

    @FXML private Label zona;
    @FXML private TextField campo;

    @FXML
    private void pulsarBoton() {
        System.out.println("¡Botón pulsado!");
    }

    @FXML
    private void clicEnZona(MouseEvent evento) {
        if (evento.getClickCount() == 2) {
            zona.setText("¡Doble clic!");
        }
    }

    @FXML
    private void teclaPulsada(KeyEvent evento) {
        if (evento.getCode() == KeyCode.ENTER) {
            System.out.println("Has escrito: " + campo.getText());
        }
    }
}
```

> [!NOTE] La lógica está en el controlador
> El FXML solo **nombra** el método que se ejecuta; el código del manejador está en el controlador. Así, la vista sigue sin contener lógica.

## 7.4. Manejadores desde código Java

Cada atributo `onXxx` del FXML tiene su método **`setOnXxx()`** en Java: `setOnAction()`, `setOnMouseClicked()`, `setOnKeyPressed()`… Reciben el manejador, que normalmente se escribe como una **expresión lambda** (`evento -> { … }`):

```java
Button boton = new Button("Haz clic");
boton.setOnAction(evento -> System.out.println("¡Botón pulsado!"));

Label zona = new Label("Haz doble clic aquí");
zona.setOnMouseClicked(evento -> {
    if (evento.getClickCount() == 2) {
        zona.setText("¡Doble clic!");
    }
});

TextField campo = new TextField();
campo.setOnKeyPressed(evento -> {
    if (evento.getCode() == KeyCode.ENTER) {
        System.out.println("Has escrito: " + campo.getText());
    }
});
```

Es la opción necesaria cuando los nodos se crean desde Java, y también se puede usar en el `initialize()` de un controlador para nodos definidos en el FXML.

Un programa completo, sin FXML:

```java
import javafx.application.Application;
import javafx.scene.Scene;
import javafx.scene.control.Button;
import javafx.scene.layout.StackPane;
import javafx.stage.Stage;

public class EjemploSinFXML extends Application {

    @Override
    public void start(Stage ventana) {
        Button boton = new Button("Haz clic");
        boton.setOnAction(evento -> System.out.println("¡Botón pulsado!"));

        ventana.setTitle("Ejemplo sin FXML");
        ventana.setScene(new Scene(new StackPane(boton), 300, 200));
        ventana.show();
    }

    public static void main(String[] args) {
        launch(args);
    }
}
```

## 7.5. Información del evento

El objeto del evento permite saber exactamente qué ha hecho el usuario. Cada tipo de evento tiene sus propios métodos; estos son los más útiles:

| Evento | Método | Devuelve |
|---|---|---|
| Todos | `getSource()` | El nodo que ha producido el evento. Útil si un mismo manejador atiende a varios botones. |
| `MouseEvent` | `getClickCount()` | Número de clics seguidos: 1 (clic) o 2 (doble clic). |
| `MouseEvent` | `getButton()` | El botón pulsado: `MouseButton.PRIMARY` (izquierdo), `SECONDARY` (derecho) o `MIDDLE`. |
| `MouseEvent` | `getX()`, `getY()` | La posición del ratón dentro del nodo. |
| `KeyEvent` | `getCode()` | La tecla pulsada, como constante de `KeyCode` (`ENTER`, `ESCAPE`, `A`, `DIGIT1`…). En `onKeyPressed` y `onKeyReleased`. |
| `KeyEvent` | `getCharacter()` | El carácter escrito. Solo en `onKeyTyped`. |
| `KeyEvent` | `isControlDown()`, `isShiftDown()` | Si se mantenía pulsada la tecla Ctrl o Mayús. |

Por ejemplo, un manejador de clics que distingue el botón y el número de clics:

```java
zona.setOnMouseClicked(evento -> {
    if (evento.getButton() == MouseButton.PRIMARY && evento.getClickCount() == 2) {
        System.out.println("Doble clic con el botón izquierdo");
    } else if (evento.getButton() == MouseButton.SECONDARY) {
        System.out.println("Clic con el botón derecho");
    }
});
```

> [!WARNING] `getButton()` y no `isPrimaryButtonDown()`
> `isPrimaryButtonDown()` indica si el botón **sigue pulsado**. En `onMouseClicked`, el evento llega cuando ya se ha soltado, así que devuelve `false`. Para saber qué botón se ha pulsado, usa `getButton()`.
